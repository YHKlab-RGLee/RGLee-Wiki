# 문서별 독립 사실 검토

과학적 집필의 기본 구성은 작성자와 독립 사실 검토자 한 명이다. 메인은 범위 확정·기록 등록·최종 검증을 담당한다. 사실 검증 기준과 기록 형식은 `refs/quality/README.md`를 따른다.

| 역할 | 스킬 | 책임 |
| --- | --- | --- |
| 작성자 (`wiki_revision` 또는 메인) | `revise-wiki-article` / `research-and-write-wiki` | 요청한 집필·수정과 출처 확인 |
| `wiki_references` | `audit-wiki-references` | 최종 주장·출처·계산의 독립 대조 |
| `wiki_quality` (선택) | `assess-wiki-article` | 사용자가 요청한 구성·설명력 조언; 점수·등록·게시 차단 없음 |
| 메인 | `evaluate-wiki-quality` | 기준 버전·범위 확인, registry 쓰기와 최종 build |

별도 종합 품질 평가자를 기본 절차에 추가하지 않는다. 추가 사실 검토자는 해결되지 않은 문헌·판정 충돌 또는 사용자의 명시적 요청에만 배정한다. 독립 검토를 실행하지 못하면 그 사실을 밝히고 작성자의 자기평가로 대체하지 않는다. Navigation·의미 보존 편집·도구 변경에는 과학 검토 agent를 자동 추가하지 않는다.

## 범위와 입력

- 각 agent는 한 문서의 한 역할을 맡는다. 여러 문서는 문서별로 순차 완료한다. 선행 문서를 읽을 수 있지만 검토 대상을 임의로 늘리지 않는다.
- 새 독립 검토자는 `fork_turns: none`으로 시작한다. 저장소 경로, 역할, 최종 파일과 SHA, 마지막 검증 버전, 요청 범위·제약, 고유한 `experiment/<task>/<page>/<role>/` 출력 경로를 전달한다.
- 작성 대화·자기평가·이전 점수·통과 기대는 주지 않는다. 초기 발견을 남긴 뒤 필요한 이전 근거의 범위와 provenance를 확인해 재사용한다.
- 검토 기준은 최근 커밋 하나가 아니라 마지막 검증 버전이다. 변경된 주장과 영향을 받는 정의·가정·결론을 대조한다. 범위 확대의 이유를 밝히되 불변 출처를 이유 없이 다시 조사하지 않는다.

## 소유권과 순서

작성 완료 → 버전 고정 → 독립 사실 검토 → 필요한 수정과 해당 범위 재검토 → 메인 등록 → 자동 검사와 strict build 순서로 진행한다. 검토자는 article·registry·정책을 수정하지 않고 지정된 experiment 디렉터리에만 결과를 작성한다. 작성자는 다른 사람의 수정을 되돌리지 않는다. 버전이 바뀌면 오래된 평가를 등록하지 않는다.

메인은 source SHA, 범위와 근거 파일, 미해결 항목을 확인하고 registry 쓰기를 직렬 실행한다. 사실 검토자에게 빌드 결과를 전달하여 평가 문서를 재작성하게 하지 않는다. 렌더링은 별도 자동 게이트이며 메인이 한 번 실행한다.

## 간결한 전달

완료 응답에는 문서 경로·실제 확인한 SHA, `completed`/`unverified`/`stale`, 확인 범위, 미해결 항목 수와 결과 경로만 적는다. 상세 주장 근거는 facts YAML에 둔다. 상태가 completed라는 사실은 과학적 통과를 뜻하지 않는다. mismatch와 접근 불가·근거 부족을 구별한다. 검토 모델 정보는 확인 가능한 값만 기록한다.
