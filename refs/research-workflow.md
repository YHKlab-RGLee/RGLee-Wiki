# Research Documentation Principles

이 위키는 미리 정한 교과서 목차를 채우지 않는다. 연구자가 요청한 advanced topic을 그때그때 조사하고, 검증을 통과한 내용만 세 고정 분야에 축적한다.

## 1. Core Principles

모델의 사전 지식은 출처가 아니라 **일관성 검사**에 사용한다. 본문에 채택하는 비자명한 주장은 모델의 과학 지식과 모순되지 않으며, 관련 내용을 직접 확인한 서로 독립적인 참고문헌 두 개 이상이 같은 범위와 가정 아래 지지해야 한다.

URL이 여러 개라는 사실만으로 근거가 독립적이지는 않다. 같은 논문의 프리프린트·출판본·저장소 사본, 한 원출처를 반복하는 여러 요약문은 각각 하나의 근거로 센다.

## 2. Research-to-Publication Workflow

1. **질문을 한정한다.** 다룰 대상, 깊이, 제외 범위와 독자를 먼저 정한다.
2. **출처 지형을 찾는다.** 원 논문, 권위 있는 리뷰 또는 대학원 수준 교재, 공식 문서를 우선 탐색한다.
3. **본문을 직접 확인한다.** 검색 결과 요약이나 서지 목록만으로 주장과 참고문헌을 연결하지 않는다.
4. **주장 단위로 교차검증한다.** 복합 문장을 원자적 주장으로 나누고, 각 주장에 독립 출처 두 개 이상을 대응시킨다.
5. **출처의 독립성을 확인한다.** 같은 데이터·논문·문서에서 파생된 설명을 중복 근거로 세지 않는다.
6. **규약을 맞춘다.** 용어, 기호, 단위계, 부호, 좌표축, 정규화와 근사의 범위를 하나의 규약으로 변환해 비교한다.
7. **채택 여부를 결정한다.** 지식과 출처가 일치하면 작성하고, 불확실하면 추가 조사하며, 해결되지 않으면 제외한다.
8. **인용과 함께 작성한다.** 비자명한 주장 바로 뒤에 다중 출처 인용을 둔다.
9. **문서 변경을 즉시 동기화한다.** 본문, index 또는 다른 Markdown 페이지를 작성·수정한 직후 `./quality.sh sync`를 실행한다. 이전 평가는 이력으로 보존되고 현재 평가는 재평가 대기로 전환되어야 한다.
10. **문서 품질을 닫힌 고리로 점검한다.** `$evaluate-wiki-quality`로 `topic`, `scope`와 원문이 관련된 같은 종류의 문서를 두 개 이상 실시간으로 고른다. 대상 문서의 글자 수와 설명 요소 합계가 각각 비교 평균의 80%에 도달하는지 확인하고, 미달한 설명을 보강한다. 정량 기준을 만족한 뒤 내용·근거·설명·형식을 평가하며, 각 보완 뒤에 다시 동기화·평가한다.
11. **게시 전 검증한다.** `./quality.sh check <page> <changed-index-page...>`로 변경된 모든 Markdown 문서의 품질 기록이 현재 내용과 일치하고 `pass`인지 확인한 뒤 `refs/format.md`의 검증 완료 조건과 엄격한 MkDocs 빌드를 모두 통과시킨다.

## 3. Source Selection

주장 성격에 따라 다음 조합을 우선한다.

| 주장 성격 | 우선 조합 |
| --- | --- |
| 이론의 원래 정의·유도 | 원 논문 + 권위 있는 리뷰 또는 대학원 수준 교재 |
| 현재의 학술적 합의 | 복수의 독립 리뷰 + 필요한 원 논문 |
| 수치·실험 결과 | 원 연구 + 독립 재현 또는 별도 데이터셋의 연구 |
| 소프트웨어의 현재 동작 | 공식 문서·릴리스 자료 + 독립적인 사용 또는 분석 자료 |
| 규약·표준 | 표준 또는 공식 명세 + 해당 분야의 권위 있는 적용 문헌 |

블로그, 검색 요약, 출처 없는 강의 노트와 생성형 AI의 답변은 탐색 단서로만 사용할 수 있으며 최종 근거로 세지 않는다.

## 4. Conflicts and Exceptions

출처가 충돌하면 실험 조건, 정의, 근사, 표본, 버전과 규약의 차이를 먼저 확인한다. 차이가 해소되지 않으면 하나를 임의로 선택하지 않는다. 충돌 자체가 문서의 중요한 내용일 때에는 각 입장의 적용 범위와 근거를 함께 제시하고, 그렇지 않으면 해당 주장을 제외한다.

독립 출처를 두 개 확보할 수 없는 주장은 검증 완료 문서에 넣지 않는다. 꼭 보존해야 한다면 연구자의 명시적 승인 아래 미검증 초안으로만 남기고 탐색 메뉴에는 추가하지 않는다.

## 5. Proven-Method Log

여기는 실제 콘텐츠 작업에서 효과가 확인된 재사용 방법만 누적하는 로그이다. 단순한 아이디어나 주제별 과학 지식은 기록하지 않는다. 새 항목에는 날짜, 적용한 콘텐츠, 방법, 효과를 확인한 기준, 재사용 조건과 예외를 짧게 남긴다.

### (1) Entry Template

```markdown
### (N) YYYY-MM-DD — Method Name

- 적용 콘텐츠:
- 방법:
- 확인 기준:
- 재사용 조건:
- 예외 또는 한계:
```

### (2) 2026-07-31 — Licensed Representative Figure Acquisition

- 적용 콘텐츠: MOSFET 대표 누설 전류와 단채널 효과
- 방법: 주요 절의 도입에 필요한 schematic을 먼저 정한 뒤, CC BY-SA 자료는 라이선스·저자·수정 여부를 확인하여 로컬에 저장하고, 재사용 조건이 불명확한 논문 그림은 복제하지 않고 원문의 figure로 연결했다.
- 확인 기준: 네 대표 그림이 hotlink 없이 strict MkDocs 빌드 결과에 포함되고, 각 캡션과 참고문헌에 출처·라이선스·수정 여부가 남는지 검사했다.
- 재사용 조건: 기존 그림이 개념 이해를 실질적으로 돕고 저자와 재사용 조건을 원본 페이지에서 확인할 수 있을 때 사용한다.
- 예외 또는 한계: 공개 라이선스 schematic도 정량 근거로 사용하지 않는다. 물리 주장은 독립적인 교재·원 논문으로 별도 교차검증한다.
