# 검증된 과학 문서 작성 형식

이 문서는 새 과학 문서와 명시적으로 재구성하는 기존 문서에 적용하는 형식을 정의한다. 프로젝트의 구조·언어·범위 규칙은 `AGENTS.md`, 조사 절차는 `refs/research-workflow.md`를 따른다.

## 1. 파일과 메타데이터

- 파일명과 디렉터리명은 영문 소문자 케밥 표기법(kebab-case)을 사용한다.
- 문서는 적절한 고정 도메인과 주제 그룹 아래에 둔다.
- 검증을 마치고 탐색 메뉴에 포함하는 문서는 최상단에 다음 메타데이터를 둔다.

```yaml
---
title: "1.1. Domain or object: Topic"
description: 문서의 범위와 목적을 설명하는 한 문장
status: verified
last_verified: YYYY-MM-DD
---
```

- 메타데이터를 사용하더라도 본문 첫 제목은 `# 1.1. Domain or object: Topic`처럼 주제 그룹과 문서의 소수 번호를 포함한 전체 제목으로 명시한다.
- `status: verified`는 본문에 채택한 비자명한 주장이 다중 출처 기준을 통과했다는 뜻이다. 초안이나 미검증 문서에는 사용하지 않는다.

## 2. 기본 문서 구조

본문을 쓰기 전에 먼저 표준 교재와 권위 있는 리뷰에서 해당 주제를 설명하는 순서를 비교하여 **교과서적 목차**를 확정한다. 목차는 독자가 개념을 의존 순서대로 이해할 수 있도록 다음 흐름을 우선한다.

1. 정의와 범위
2. 선행 개념과 기준 모형
3. 물리적 기원과 지배 방정식
4. 주요 현상 또는 방법
5. 측정과 정량 지표
6. 한계, 혼동 요인과 적용 범위
7. 요약과 참고문헌

자료를 찾은 순서, 작성자의 사고 순서 또는 확보한 그림의 순서로 절을 나열하지 않는다. 먼저 전체 목차에서 각 절의 역할과 선행 관계를 정한 뒤, 검증한 내용을 그 틀 안에 채운다. 하나의 현상을 설명할 때에는 물리적 원인 → 지배 방정식 또는 모형 → 물리적 결과 → 측정 → 정량 지표 → 해석상의 주의점 순서를 기본으로 한다.

목차는 세부 사실을 빠짐없이 나열하는 목록이 아니라 글의 핵심 개념과 논리적 관계를 보여 주는 구조여야 한다. H2에는 주제를 이해하는 데 필수적인 개념·모형·현상·방법을 두고, 조건별 차이, 개별 사례와 해석상의 예외는 독립적인 논점일 때만 H3로 분리한다. 같은 층의 절은 가능한 한 같은 개념 수준과 분류 기준을 유지하며, 한두 문단으로 끝나는 지엽적인 내용을 목차 항목으로 만들지 않는다.

문서 전체와 각 절에서는 가장 중요한 개념 설명을 먼저 제시하고 세부 사항을 뒤에 둔다. 먼저 대상의 정의, 핵심 관계와 물리적 의미를 밝혀 독자가 무엇을 이해해야 하는지 알게 한 뒤, 방정식의 세부 항, 조건별 거동, 측정 절차, 예외와 한계를 전개한다. 배경 지식이 필요하더라도 중심 개념을 불필요하게 늦추지 않으며, 긴 선행 설명은 기존 문서로 연결하거나 핵심 개념을 이해하는 데 필요한 범위로 제한한다.

같은 문서 안에서 하나의 정의, 원인, 식의 물리적 의미와 결론을 새 정보 없이 반복하지 않는다. 가장 완전한 설명을 논리적으로 적절한 한 곳에 두고, 뒤에서 다시 필요하면 짧게 가리킨 뒤 새로운 조건·적용·측정·한계로 바로 이어 간다. 도입부의 범위 제시와 마지막 요약처럼 기능이 분명한 반복, 일반식에서 근사식으로 이어지는 유도와 서로 다른 조건을 비교하는 설명은 중복으로 간주하지 않는다.

이 흐름은 점검 목록이지 고정된 절 제목이 아니다. 공통 기준 모형, 기호와 측정 규약을 별도의 선행 문서가 이미 설명한다면 해당 문서에 연결하고, 현재 글은 주제를 대표하는 물리 현상·방법·대상으로 바로 시작한다. `범위와 규약`은 여러 문헌의 부호·좌표·정규화가 실제로 충돌하거나 글의 유효 범위를 먼저 제한해야 할 때만 독립 절로 둔다. 짧은 가정은 도입 문장이나 관련 식 바로 옆에서 밝힌다.

기술 문서는 주제와 선행 문서의 존재 여부에 따라 다음 두 구조 가운데 적절한 쪽을 조정하여 사용한다.

```markdown
# 1.1. Domain or object: Topic

주제의 정의, 목적, 범위를 설명하는 짧은 도입부.

## 1. 기준 모형과 핵심 개념

비교 기준이 되는 이상적 모형과 필요한 정의·선행 개념.

## 2. 물리적 기원과 지배 이론

변수, 지배 방정식, 가정, 계산 절차.

## 3. 주요 현상 또는 방법

현상 또는 방법을 동일한 분류 기준과 설명 순서로 전개.

## 4. 측정 또는 평가

측정·계산 조건, 추출 절차, 정량 지표와 비교 규약.

## 5. 한계와 해석

근사, 유효 범위, 혼동하기 쉬운 현상과 알려진 한계.

## 6. 요약

핵심 내용을 간결하게 정리한 목록.

## 7. 참고문헌

검증한 출처 목록.
```

공통 기준 문서가 있는 후속 글은 다음처럼 시작할 수 있다.

```markdown
# 1.2. Domain or object: Topic

공통 기호와 기본 측정 규약은 [선행 문서](prerequisite.md)를 따른다.

## 1. 대표 현상과 물리적 기원

현재 글의 중심 현상을 바로 정의하고 설명한다.
```

## 3. 제목과 문체

- 문서 제목과 탐색 메뉴는 분야에서 가장 대표성 있는 영문 표현을 사용한다.
- 영문 제목은 sentence case를 사용한다. 첫 단어의 첫 글자만 대문자로 쓰되, `MOSFET`, `SRAM`, `GW`, `NEGF`, `e3nn`과 같은 약어·고유명사·관례적 표기는 원래 대소문자를 유지한다.
- 용어는 **전문용어**와 **설명어**로 먼저 구분한다. 개념·현상·모형·방법·parameter·algorithm·representation·소자 구조·표준 회로 블록을 식별하는 전문용어는 대표적인 영문 표현을 사용한다.
- `enhancement mode`, `depletion mode`, `body effect`, `subthreshold leakage`, `compact model`, `potential-energy surface`, `feature`, `principal layer`처럼 영문 표현 자체가 분야의 식별자 역할을 하는 용어는 임의로 번역하지 않는다. 구성 단어를 하나씩 옮겨 새 한국어 합성어를 만들지 않는다.
- 글을 교정할 때 영어의 비율을 줄이는 것을 목표로 삼지 않는다. 기존의 전문용어를 한국어로 치환하지 말고, 필요한 경우 첫 등장 뒤에 자연스러운 한국어 문장으로 뜻을 설명한다.
- 전류, 전압, 소자, 조건, 곡선, 경로, 영역, 전기장, 장벽, 성분, 측정, 정량 지표, 추출 구간, 기준, 의존성처럼 문장 안에서 일반적인 대상·상태·동작·관계를 나타내는 설명어는 한국어로 쓴다. 같은 단어라도 고유한 전문용어의 일부이면 대표 영문 표현을 보존한다.
- 자연스러운 한국어 문체는 전문용어를 번역한다는 뜻이 아니다. 영문 전문용어를 명사구로 유지하되 조사, 서술어, 조건, 인과관계와 문단의 논리 흐름을 한국어 어순으로 구성한다.
- 영문 원문의 수동태, 긴 전치사구와 명사 나열을 그대로 옮기지 않는다. 주체·조건·결과를 분명히 나누고, 한 문장에 독립적인 주장을 과도하게 겹치지 않는다.
- 전문용어가 연속해서 등장해도 용어 자체를 바꾸지 않는다. 대신 문장을 나누거나 한국어 서술어를 보강하여 각 용어 사이의 관계가 바로 드러나게 한다.
- 절 제목은 한국어를 기본으로 한다. 문서의 중심 개념이나 정립된 현상·방법·모형을 직접 이름 붙일 때에만 영문 표현을 남긴다.
- 절 제목은 핵심 개념을 식별할 수 있는 짧은 명사구를 원칙으로 한다. 완결된 문장, 질문형 표현, 세부 결론을 그대로 옮긴 서술형 제목은 피한다. 예를 들어 `온도가 증가하면 carrier mobility가 감소한다`보다 `Carrier mobility의 온도 의존성`을 사용한다.
- 제목만 읽어도 글의 논리적 뼈대가 드러나야 한다. 제목에 조건, 원인과 결과를 모두 압축해 넣기보다 대표 개념을 제목으로 두고 구체적인 관계는 해당 절의 첫 문단에서 설명한다.
- 표의 일반 열 제목과 설명 셀은 한국어로 쓴다. 독자가 일관되게 식별해야 하는 핵심 용어, 기호, 약어와 표준 명칭만 영어로 유지할 수 있다.
- H1 문서 제목은 주제 그룹 번호와 그룹 안 문서 번호를 `1.1.` 형식으로 표시한다.
- H2 주 절은 `1.`, `2.`처럼 번호를 붙인다.
- H3 하위 절은 `(1)`, `(2)`처럼 번호를 붙인다.
- 문서 목차에는 H2와 H3의 두 층만 허용하며 H4 이하는 사용하지 않는다.
- 사이트 탐색 메뉴에는 고정 도메인 아래에 topic-group 층을 하나 둔다. 그룹은 `1. MOSFET`, 문서는 `1.1. Basic operation`처럼 표시한다.
- 탐색 메뉴의 topic-group 층은 관련 문서를 빠르게 좁히기 위한 정보 구조이며, 문서 내부 목차의 깊이를 늘리지 않는다.
- 그룹 번호는 고정 도메인 안에서 `1.`, `2.` 순서로, 문서 번호는 그룹 안에서 `1.1.`, `1.2.` 순서로 부여한다.
- 탐색 메뉴의 문서 라벨은 반복되는 그룹명을 생략한 짧은 제목을 사용할 수 있다. front matter와 H1에는 검색과 문맥 식별을 위해 `1.1. MOSFET: Basic operation`처럼 그룹명을 포함한 전체 제목을 쓴다.
- 본문은 `~이다`, `~한다`, `~할 수 있다`와 같은 기술 서술체를 사용한다.
- 한 문단에는 하나의 중심 논지를 둔다.
- 추상적인 정의, 여러 단계의 인과관계, 방정식의 물리적 의미처럼 독자가 처음 읽을 때 어려울 수 있는 부분에는 `예를 들어`와 같은 연결 표현을 사용하여 보충 설명을 덧붙인다. 예시는 특정 물질·소자·경계 조건·계산 단계 또는 제한적인 경우처럼 본문 개념을 직접 적용할 수 있는 학술적 사례를 우선한다.
- 예시는 앞선 설명을 대신하지 않고 정의나 일반 관계를 구체화해야 한다. 일상적 비유, 의인화와 지나친 단순화로 정확한 적용 범위가 흐려질 수 있으면 사용하지 않으며, 예시에도 본문과 같은 가정·기호·인용 기준을 적용한다.
- 약어가 있는 핵심 용어는 문서에서 처음 등장할 때 `full English name (ABBR.)` 순서로 쓴다. 이해에 실질적으로 도움이 될 때에만 한국어 뜻을 한 번 보조한다.

```markdown
Density functional theory (DFT)는 전자 밀도를 기본 변수로 사용한다.
```

- 약어는 반드시 영문 전체 명칭을 먼저 제시한 뒤에 사용한다. 초록, 그림 캡션, 표와 알림 블록도 약어의 최초 정의 위치로 간주하므로 문서의 실제 읽기 순서에서 정의되지 않은 약어가 먼저 나오지 않게 한다.
- 분야의 대표 문서 제목에 약어가 포함되는 경우 제목에서 먼저 쓸 수 있다. 이때 본문 첫 문장에서 `full English name (ABBR.)` 형식으로 반드시 확장한다.
- 한국어 문장의 첫머리에 영문 보통명사가 오면 첫 영단어의 첫 글자를 문장식으로 대문자화한다. 표현 전체를 제목식 대문자로 바꾸지는 않는다. 고유명사, 약어, 기호와 `nMOS`, `p-type`처럼 첫 소문자 자체가 표기의 일부인 용어는 관례적인 대소문자를 유지한다.

```markdown
Subthreshold leakage는 문턱전압 아래에서 흐르는 누설 전류이다.
```

위 예에서는 문장 첫머리의 `Subthreshold`만 대문자로 시작한다. `Subthreshold Leakage`처럼 제목의 Title Case를 본문 문장에 옮기지 않는다.
- 최초 정의 이후에는 선별한 영문 대표 용어 또는 정의한 약어를 사용하고 문서 전체에서 일관되게 유지한다.
- 이미 정의한 영문 전체 명칭이나 한국어 뜻을 반복 병기하지 않는다. 같은 개념을 영문, 한국어, 약어로 불규칙하게 번갈아 쓰지 않는다.
- 고유한 방법·모형·소프트웨어 이름과 분야의 정립된 대표 표현은 관례적인 영문 표기를 유지한다. 일반적인 설명어까지 이 규칙으로 영어화하지 않는다.

## 4. 정의와 기호

핵심 용어는 처음 사용할 때 명확히 정의한다.

```markdown
**density of states (DOS)**는 단위 에너지 구간에 존재하는 양자 상태의 수를 나타낸다.
```

수식에 나타나는 기호는 수식 전후에서 정의하며, 한 문서 안에서 같은 기호를 다른 의미로 재사용하지 않는다.

- 분야에서 복수의 규약을 사용하는 경우 선택한 규약을 공통 기준 문서, 도입 문단 또는 필요한 경우에만 두는 `범위와 규약` 절에 밝힌다.
- 출처의 규약이 서로 다르면 같은 규약으로 변환한 뒤 비교하고, 필요한 변환 관계를 독자에게 제시한다.
- 단위계, 부호, 축 방향, 정규화, 지수 표기, 약어와 번역어를 문서 전체에서 일관되게 유지한다.
- 같은 계열의 현상은 물리적 원인, 방정식, 결과, 측정, 정량 지표, 해석상의 주의점 순서를 동일하게 맞춘다.
- 표와 본문, 그림 캡션 사이에서 같은 물리량에 동일한 기호·단위·부호를 사용한다.
- 전류를 부호 있는 값으로 쓸지 크기로 쓸지, 면적·폭·길이 가운데 무엇으로 정규화할지 문서 시작에서 정하고 끝까지 유지한다.
- `metric`, `sweep`, `extraction window`, `device split`이 특정 방법의 이름이 아니라 실험 절차를 일반적으로 설명하는 말이면 각각 `정량 지표`, `전압 주사`, `추출 구간`, `소자군`처럼 쓴다. 이 규칙을 전문용어의 자동 번역에 적용하지 않는다.

## 5. 수식

인라인 수식은 `$E = \hbar\omega$`처럼 쓰고, 독립 수식은 다음과 같이 쓴다.

```markdown
$$
E = \hbar\omega
$$
```

- 방정식의 가정과 각 기호의 의미를 설명한다.
- 정확한 관계와 근사식을 구분한다.
- 유도 과정을 생략할 때는 생략 범위를 명시한다.

## 6. 그림과 표

그림과 수식은 장식이 아니라 물리적 구조, 전류 경로, 에너지 장벽, 측정 바이어스와 정량 지표의 추출법을 빠르게 이해시키는 수단으로 적극 사용한다.

- 그림이 이해를 실질적으로 돕는 주요 절은 도입 문단 직후에 대표 개략도 또는 대표 측정 곡선을 둔다.
- 소자 구조를 다루는 절에는 단자, 전류 경로, 전기장 방향 또는 공핍 영역을 표시한 개략도를 우선한다.
- 측정을 다루는 절에는 단자 바이어스 구성이나 정량 지표를 추출하는 대표 곡선을 우선한다.
- 한 그림이 여러 절의 공통 구조를 충분히 설명하면 반복하지 않고 내부 링크로 다시 가리킨다.
- 적합한 기존 그림이 없거나 재사용 조건이 불명확하면 억지로 그림을 넣지 않는다.

```markdown
<figure markdown="span">
  ![MOS capacitor의 equilibrium band diagram](images/mos-capacitor-band-diagram.svg)
  <figcaption markdown="1">
    그림 1. MOS capacitor의 equilibrium band alignment.
    출처: A. Author, "Original Title," Fig. 2, CC BY 4.0.[1]
  </figcaption>
</figure>
```

- 모델이 새 그림을 생성하지 않는다. 논문, 교재, 표준, 공식 문서 또는 공개 저장소에서 목적에 맞는 기존 그림을 찾는다.
- 원본 파일을 저장소에 포함하기 전에 라이선스 또는 명시적 재사용 조건을 확인한다. CC BY, CC BY-SA, CC0 또는 public domain 자료를 우선한다.
- 재사용 조건을 확인할 수 없으면 그림을 복제하지 않고 원출처의 해당 figure로 연결한다.
- 재현하거나 수정한 그림에는 원저자, 원문 제목, figure 번호, URL 또는 DOI, 라이선스, 수정 여부를 캡션과 참고문헌에 밝힌다.
- 원본을 자르거나 표식을 추가한 경우 `수정하여 재현`이라고 명시하고 원본의 의미를 바꾸지 않는다.
- 외부 서버의 이미지 파일을 직접 hotlink하지 않고, 재사용이 허용된 파일만 관련 `images/` 디렉터리에 보관한다.
- 모든 그림에는 의미 있는 대체 텍스트와 한국어 설명을 포함한다.
- 그림 캡션은 `<figcaption markdown="1">`으로 작성한다. 캡션 안의 인라인 수식은 `$...$` 형식을 사용해 MathJax가 렌더링할 수 있게 한다.
- 표에는 내용을 식별할 수 있는 제목 또는 앞선 설명을 둔다.

수식은 핵심 물리 관계와 정량 지표의 정의를 설명하는 데 충분히 사용하되, 각 수식의 가정, 기호, 단위와 실험 자료에서의 추출법을 바로 설명한다.

## 7. 코드와 명령

코드 블록에는 언어를 지정하고, 실행 조건이나 입력값이 중요하면 바로 앞에서 설명한다.

````markdown
```python
energy = hbar * omega
```
````

명령, 코드 식별자, 파일명, 소프트웨어명은 번역하지 않는다.

## 8. 알림 블록

Material for MkDocs의 기본 알림 블록을 사용한다.

```markdown
!!! note "가정"
    이 식은 열평형을 가정한다.

!!! warning "적용 범위"
    비평형 조건에는 직접 적용할 수 없다.
```

장식 목적이 아니라 가정, 한계, 주의사항, 예제를 구분할 때만 사용한다.

각 현상의 설명 뒤에서는 측정 절차와 실제 추출식을 `[Measurement]` 블록 안에 함께 둔다. 독자가 “어떤 곡선을 얻는가”에서 “무엇을 계산하는가”로 한 번에 이어서 읽을 수 있어야 한다.

```markdown
!!! info "[Measurement]"
    단자 연결, 고정 바이어스, 주사 변수와 필요한 소자군을 설명한다.
    이어서 실제 측정값으로부터 계산하는 정량 지표의 정의식, 단위와 추출 구간을 제시한다.
```

- `[Measurement]`에는 무엇을 어떻게 측정하는지와 그 자료에서 계산하는 대표 정량 지표를 함께 쓴다.
- 추출식은 `DIBL = \Delta V_T/\Delta V_D`, `SS=(d\log_{10}|I_D|/dV_G)^{-1}`처럼 실제 계산에 바로 쓸 수 있는 형태로 제시한다. “기울기를 본다”, “이동량을 비교한다”처럼 정량 정의가 빠진 설명만 두지 않는다.
- 보고해야 할 바이어스, 온도, 정규화 기준, 회귀 또는 fitting 구간과 통계량이 길면 `!!! abstract "[Metric]"`을 선택적으로 추가할 수 있다. 이 블록은 대표 추출식을 `[Measurement]`에서 감추는 용도로 사용하지 않는다.
- 해석상의 혼동 요인과 예외는 필요하면 `!!! warning "[Interpretation Caveat]"`로 분리한다.
- 여러 현상을 비교하는 요약 표의 일반 열 이름도 `측정`, `정량 지표`, `주요 혼동 요인`처럼 한국어로 쓴다.

## 9. 내부 링크

- 존재하는 문서에만 상대 경로로 연결한다.
- 링크 문구가 scientific concept이나 article title을 가리키면 representative English expression을 사용한다.
- 선행 개념은 처음 필요한 위치에서 연결하고, 같은 링크를 과도하게 반복하지 않는다.

## 10. 참고문헌과 인용

본문 인용은 대괄호 번호를 사용한다. 비자명한 주장은 원칙적으로 서로 독립적인 두 개 이상의 출처를 같은 인용 묶음에 둔다.

```markdown
이 근사는 특정 조건에서 유효하다.[1,2]
```

참고문헌은 등장 순서로 정리한다.

```markdown
## 8. 참고문헌

1. A. Author and B. Author, "Article Title," *Journal Name* **Volume**, pages (Year). DOI 또는 URL.
2. A. Author, *Book Title*, Edition (Publisher, Year).
3. Software Project, "Documentation Page Title," 공식 문서 URL.
```

- 서지 정보와 링크가 실제 주장을 뒷받침하는지 확인한다.
- 검색 결과의 요약문만 보고 인용하지 않는다. 본문 또는 공식 문서의 관련 구절을 직접 확인한다.
- 같은 논문의 미러, 프리프린트, 출판본은 하나의 근거로 센다.
- 출처가 다른 원출처 하나를 반복 인용한다면 독립 근거로 간주하지 않는다.
- 모델의 사전 지식은 출처가 아니라 일관성 검사에만 사용한다.
- 모델 지식과 다중 출처가 같은 범위·가정 아래 일치하지 않으면 추가 조사하거나 해당 주장을 본문에서 제외한다.
- 출처가 충돌하면 차이를 명시적으로 다룰 수 있을 때만 쟁점으로 서술한다. 임의로 합의된 결론을 만들지 않는다.
- 탐색 메뉴에 포함된 문서에는 미확인 주장, 깨진 링크, 검증 대기 주석을 남기지 않는다.

## 11. 검증 완료 조건

다음 조건을 모두 만족해야 `status: verified`로 게시할 수 있다.

1. 본문의 비자명한 주장마다 두 개 이상의 독립 출처가 같은 의미를 지지한다.
2. 인용한 모든 출처의 관련 내용을 직접 확인했다.
3. 모델의 사전 지식과 출처 사이에 해결되지 않은 충돌이 없다.
4. 용어, 기호, 단위, 부호, 좌표계와 근사의 범위가 일관된다.
5. 추론은 확립된 결과와 구분되어 있고, 추론의 근거가 인용되어 있다.
6. 참고문헌의 저자, 제목, 발행 정보, DOI 또는 URL을 확인했다.
7. 검증되지 않은 수치, 방정식, 인용문, 소프트웨어 동작 설명이 없다.

## 12. 잘 쓴 예시와 비교

새 과학 문서와 대폭 개정한 과학 문서는 완성 단계에서 `refs/writing-benchmarks/high/`의 가장 가까운 예시와 비교한다.

양적으로 필요한 내용이 충분한지, 질적으로 설명과 근거가 충실한지, 형식적으로 같은 수준으로 정돈되었는지 확인한다. 주제에 맞지 않는 분량이나 구성 요소 수를 기계적으로 복제하지 않는다. 부족하면 보완한 뒤 다시 비교하고 완료 보고에 사용한 예시와 결과를 짧게 적는다. 자세한 비교 기준은 `refs/writing-benchmarks/README.md`에서 확인하고, 현재 예시는 `refs/writing-benchmarks/high/`에서 직접 확인한다.

예시는 작성 품질을 비교하는 자료일 뿐 과학적 출처를 대신하지 않는다.
