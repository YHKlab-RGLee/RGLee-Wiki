# 문서 품질 관리

이 디렉터리는 `docs/` 아래의 모든 Markdown 문서를 같은 방식으로 점검한 결과를 보관한다. 각 문서의 현재 상태를 숫자로 기록하고, 새 문서나 크게 고친 문서는 비슷한 문서와 비교하여 부족한 부분을 보완한다.

## 기록 파일

- `rubric.yaml`: 사람이 읽을 수 있는 네 가지 평가 항목과 통과 기준
- `documents.yaml`: 모든 문서의 주제·범위, 자동 집계값, LLM 점수와 이전 평가 이력

`documents.yaml`은 직접 계산해서 고치지 않는다. 문서 작성·수정·이동·복원·삭제 workflow에서 `$evaluate-wiki-quality` skill과 `quality.sh`를 사용한다.

`topic`은 LLM이 작성한 문서 제목에서, `scope`는 front matter의 `description`에서 가져온다. Index 문서는 첫 소개 문장을 `scope`로 사용한다. `kind`와 `group`은 문서 역할과 소속 범위를 나타낸다.

모든 품질 명령은 먼저 전체 `docs/` 트리와 품질 기록을 자동으로 동기화한다.

- 새 문서: 자동 수치를 추가하고 LLM 평가를 비워 재평가 대상으로 만든다.
- 수정 문서: 이전 수치와 평가를 `history`에 보존하고 현재 LLM 평가를 비운다.
- 삭제 문서: 현재 목록에서 제거하고 `archived_documents`에 마지막 수치·평가·이력을 보존한다.
- 복원 문서: archive의 이력을 이어받되 현재 LLM 평가는 비워 다시 읽게 한다.
- 모든 변화: 해당 문서의 `topic`, `scope`와 자동 집계값을 현재 내용에 맞춘다.

문서를 다루는 authoring workflow는 변경 직후 `./quality.sh sync`를 실행하고, 게시 전 품질 검사도 검사 전에 같은 동기화를 실행한다.

## 자동으로 세는 값

다음 두 값은 문서의 설명량을 확인하는 정량 자료이다.

- `characters`: 참고문헌, 코드와 Markdown 표기를 제외한 본문 글자 수
- `explanatory_elements.total`: 그림, 표, 독립 수식과 fenced code block 수의 합

`explanatory_elements`에는 합계와 함께 `figures`, `tables`, `equations`, `code_blocks`의 세부 수를 남긴다. 문서 특성에 따라 표, 그림, 수식과 코드의 비중이 달라질 수 있으므로 통과 여부는 세부 수가 아니라 합계로 비교한다.

## LLM이 읽고 매기는 점수

각 항목을 10점 만점으로 평가하고 네 점수의 평균을 `overall`로 기록한다.

- `content`: 주제에 필요한 내용과 한계가 빠짐없이 들어 있는가
- `evidence`: 중요한 설명이 확인한 출처와 인용으로 뒷받침되는가
- `explanation`: 정의부터 결론까지 순서가 자연스럽고 이해하기 쉬운가
- `format`: 저장소의 제목, 문체, 수식, 그림, 표와 참고문헌 규칙을 지키는가

평가는 점수만 남기지 않고 부족한 부분을 한 문장으로 함께 기록한다. 문서 index에서 `evidence`는 과학적 인용 대신 현재 문서와 링크를 정확히 반영하는지를 뜻한다.

## 실시간 비교와 통과 기준

YAML의 각 record는 해당 문서의 `topic`, `scope`, 정량 자료, 평가와 이력으로 구성된다. Codex는 평가할 때 이 metadata와 원문을 읽고, 주제·범위·문서 역할이 비슷한 같은 종류의 문서를 두 개 이상 고른다. 선택한 문서와 비교 결과는 YAML에 저장하지 않고 평가 시점마다 새로 판단한다.

스크립트는 선택한 문서들의 평균을 두 정량 항목별로 계산한다. 대상 문서의 `characters`와 `explanatory_elements.total`은 각각 비교 평균의 80% 이상이어야 한다. 이 기준에 미달하면 LLM 점수를 기록하지 않고 문서를 먼저 보강한다. 보강할 때에는 대상 주제를 설명하는 데 실제로 필요한 본문, 표, 그림, 수식 또는 code block을 추가한다.

새 문서나 크게 고친 문서는 다음을 모두 만족해야 `pass`가 된다.

1. 자동 검사에서 오류가 없다.
2. 글자 수와 설명 요소 합계가 각각 비교 문서 평균의 80% 이상이다.
3. 네 점수가 각각 7점 이상이다.
4. 네 점수의 평균이 8점 이상이다.

2026-08-13에 초기 이관한 문서의 첫 평가는 `baseline`이다. `baseline`은 내용이 바뀌지 않은 문서에만 유효하며, 이후 본문을 수정하면 새 기준으로 다시 평가하여 `pass`를 받아야 한다.

## 폐루프

```text
작성 또는 수정
  → 주제·범위와 자동 수치 갱신
  → Codex가 같은 종류의 관련 문서를 두 개 이상 실시간 선택
  → 글자 수와 설명 요소 합계를 비교 평균의 80%와 비교
  → 미달이면 필요한 설명을 보강하고 다시 동기화
  → 내용·근거·설명·형식 평가
  → pass이면 게시
  → revise이면 지적된 부분을 보완하고 다시 평가
```

보완과 재평가는 세 번까지만 반복한다. 그래도 `pass`가 되지 않으면 기준을 낮추지 않고 사람의 검토가 필요한 상태로 보고한다.

## 명령

```bash
./quality.sh sync
./quality.sh report
./quality.sh check --all --allow-baseline
```

특정 문서를 평가하는 명령은 `$evaluate-wiki-quality` skill에서 설명한다. `source_hash`가 현재 문서와 다르면 오래된 평가이므로 게시 검사를 통과하지 못한다.
