# Polish Wiki Korean

요청한 문서나 절을 한국어 문장으로 명료하게 재구성한다. 독자가 주어와 대상, 조건, 동작과 결과를 직접 파악할 수 있게 한다. 필요한 문장 성분과 연결 표현을 보충하고, 압축된 설명을 풀어 쓰며, 불필요한 표현은 덜어낸다. 의미 보존은 원문의 어순·생략·길이를 고정한다는 뜻이 아니다. 단어 치환이나 어미 교정만으로 완료하지 않는다.

독립적인 윤문 도구이며, 일반 집필·검토 workflow의 필수 단계로 추가하지 않는다. 범용 humanizer의 삭제 중심 처방, 표현별 횟수 제한, 수정률 목표, 자체 등급을 적용하지 않는다.

## 범위와 문맥

- 저장소 `AGENTS.md`와 `refs/format.md`의 문체·용어·제목 규칙을 따른다. 이미 읽은 지침은 다시 읽지 않는다.
- 대상 절과 필요한 정의·인접 문맥부터 읽는다. 주체나 조건을 확인할 수 없으면 해당 기호·개념의 정의가 있는 곳까지 읽는 범위를 넓힌다. 읽는 범위를 넓혀도 수정 범위는 요청한 문서나 절에 유지한다. 제목을 수정할 때는 문서 전체의 H1–H3 목록과 해당 절의 본문을 확인한다.
- H1, navigation, 경로, 절의 순서·계층은 별도 요청이 없으면 변경하지 않는다. 제목과 본문의 불일치를 해결하려고 과학적 내용을 추가하거나 삭제하지 않는다.

## 용어와 소절 제목

- 고유명사·전문용어는 정립된 영문 명칭을 기본으로 쓴다. 한국어 명칭이 충분히 널리 정착한 경우에만 한국어를 선택한다. 임의 번역, 새로운 합성어, 영어 비율을 줄이기 위한 치환은 하지 않는다.
- 기존 문서와 관련 선행 문서에서 확정한 대표 명칭을 우선한다. 명칭 선택이 불확실하면 기존 표기를 유지하고 보류 사항으로 알린다.
- 같은 개념에는 같은 대표 명칭을 쓴다. 제목·본문·표·캡션에서 한국어·영어·동의어를 임의로 번갈아 쓰지 않는다. 최초 정의 이후 정의한 약어를 사용하는 것은 허용하며, 수식 기호·코드 식별자·직접 인용·서지 제목은 표기 통일 대상으로 바꾸지 않는다.
- 일반적인 대상·동작·조건·관계를 설명하는 말은 한국어로 쓴다. 전문용어의 구성 요소를 따로 떼어 기계적으로 번역하지 않는다.
- H2·H3는 실제 내용을 대표하는 짧고 구체적인 명사구로 다듬는다. 선택한 전문용어는 유지하고 설명 부분은 자연스러운 한국어로 쓴다. 예: `왜 Fourier 공간이 필요한가?` → `Fourier 공간의 역할`.
- 제목에 본문에 없는 주장이나 범위를 넣지 않는다. 기존 번호 체계를 유지한다. 제목 변경으로 영향을 받는 내부 anchor 링크는 확인하고 필요한 링크만 갱신한다.
- 부분 윤문에서는 범위 밖의 용어 불일치를 보고만 한다. 표기를 통일하려고 작업을 다른 절이나 문서로 확대하지 않는다.

## 본문 윤문

- 문장 명료성의 공통 기준은 `refs/format.md`의 「3. 제목과 문체」와 그 안의 「한국어 문장 구조와 번역투 점검」에 둔다. 아래 절차로 그 기준을 적용한다. 압축된 조건, 생략된 대상, 추상적인 서술을 재구성할 때에는 [대표 문장 예시](references/sentence-revision-examples.md)의 해당 유형을 읽는다.
- 한국어 기술 서술체(`~이다`, `~한다`)를 유지한다. 불필요한 이중 피동·명사화·긴 수식어를 줄이고 대상, 조건, 동작과 결과의 관계를 분명히 쓴다. 과정 자체가 중심이거나 행위자가 불명확한 피동은 유지한다.
- 내용 없는 도입, 과장된 평가, 반복되는 강조를 덜어낸다. 문맥에서 확인되는 내용을 풀어 설명하거나 생략된 문장 성분을 보충하는 것은 윤문에 포함한다. 원문에 없는 과학적 주장이나 근거를 만드는 것과 구분한다.
- 지시어의 대상이 모호하면 원문에서 확인되는 대상명을 다시 쓴다. 정확성을 위한 용어 반복은 허용한다.
- 접속사는 인과·대조·조건·재진술을 구분하는 기능으로 판단한다. 관계가 문맥에서 확인되는데 연결 표현이 없어 흐름이 끊기면 적절한 접속사나 연결절을 보충한다. 등장 횟수만으로 삭제하거나 다른 접속사로 바꾸지 않는다.
- 문장과 문단은 설명 단위에 맞춰 나눈다. 리듬을 위한 장문 생성, 종결어미 변주, 목록의 일괄 산문화는 하지 않는다. 수정할 이유가 없는 문장은 유지한다.

## 문장 재구성과 누락 점검

1. **원문의 명제를 먼저 확인한다.** 불명확한 문장마다 대상, 조건, 관계 또는 동작, 결과, 예외·부정을 짚는다. 핵심 개념이 각 문장에서 어떤 역할을 하는지 파악한다. 전문용어의 대표 명칭은 보존하되 일반 설명어의 철자까지 고정하지는 않는다.
2. **필요한 명사는 인접 정의와 수식에서 찾는다.** 기호만 쓰였거나 주어·목적어·비교 대상이 생략되었다면 해당 물리량·대상의 이름을 확인한다. 확인한 명사를 문장에 복원하고, 압축된 조건도 풀어 쓴다. 문맥을 더 읽어도 두 해석 중 하나를 결정할 수 없으면 그 부분을 보류하고 모호한 지점을 보고한다.
3. **한국어 문장과 문단으로 다시 구성한다.** 확인한 명제를 바탕으로 주어·대상과 서술어를 연결한다. 단어를 순서대로 바꾸는 방식에 머물지 않는다. 필요한 서술어와 문장 사이의 연결 표현을 보충하고 문장을 분할·결합한다. 표현이 늘더라도 대상과 관계를 이해하는 데 필요하면 유지한다. 각 문장의 인용은 해당 주장을 계속 뒷받침하도록 배치한다.
4. **의미 보존을 대조한다.** 원문과 비교하여 핵심 개념, 고정 조건, 수량, 부정의 범위, 가능성과 보장의 차이, 시제·진행 상태, 정확한 이론과 실제 계산의 구분이 유지되는지 확인한다. 기존 정의를 풀어 설명하는 것은 허용한다. 새로운 정의를 도입하거나 외부 근거가 필요한 주장을 추가하는 작업은 별도로 구분하여 보고한다. 보충 표현이 원문에 없었다는 사실 자체를 오류로 판단하지 않는다.
5. **명료성과 흐름을 별도로 검토한다.** diff만 보지 말고 수정하지 않은 문장을 포함해 요청 범위의 완성된 문단을 읽는다. ‘무엇이/무엇을’, ‘어떤 조건에서’, ‘어떤 관계인가’를 독자가 문맥에서 파악할 수 있는지, 문장 사이의 인과·대조·재진술이 이어지는지 확인한다. 한 문장에 그 정보를 모두 반복할 필요는 없다. 의미를 보존했어도 대상이나 연결이 불명확하면 다시 구성한다. `수정할 이유가 없는 문장`은 이 점검을 통과한 문장을 뜻하며, 문법 오류가 없거나 이전부터 있던 문장이라는 뜻이 아니다.

## 의미 보존과 마무리

1. 사실, 수치, 단위, 수식, 코드, 인용과 함께 조건·적용 범위·부정·인과관계·주장의 강도를 보존한다. `가능하다`, `추정한다`, `해야 한다`를 사실 단정으로 바꾸지 않는다. 인용의 위치를 옮길 때도 뒷받침하는 주장의 범위를 유지한다.
2. 필요한 부분만 패치하고 diff에서 의미 변화, 용어 불일치, 제목과 본문의 불일치를 확인한다. 의미 보존을 확신할 수 없는 수정은 되돌리고 보고한다. 과학적 오류가 의심되면 윤문으로 고치지 않는다.
3. 검토만 요청받으면 제안만 반환한다. 문서 수정 완료 후 `./quality.sh sync --polish <문서 경로> ...`로 기존 품질 기록을 승계하고, 작업 범위 전체에 `./build.sh changed`와 `git diff --check`를 한 번 실행한다. 스킬·지침만 수정하고 `docs/`를 변경하지 않은 작업에서는 sync나 문서 review를 수행하지 않는다.
4. 수정 범위, 대표적인 수정 전후 문장과 이유, 검증 결과와 보류 사항을 간결하게 보고한다. 검사·빌드 통과는 문장 명료성 검토를 대신하지 않는다. 전체 윤문본 복제, 본문 내 윤문 보고 주석, 변경률 등급은 추가하지 않는다.
