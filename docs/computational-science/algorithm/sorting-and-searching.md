# Sorting and binary search

정렬은 원소를 정해진 비교 기준에 따라 배치하는 연산이고, 이진 탐색은 그 순서에서 답이 있을 수 없는 구간을 절반씩 제거하는 방법이다. 실제 구현에서는 정렬 방향만큼이나 동률의 순서, 원본 변경 여부, 탐색 구간의 양 끝이 중요하다. Python의 정렬 함수는 같은 키의 입력 순서를 보존하므로 여러 기준을 결합할 수 있다.[1,2,3]

이 문서는 Python 3.10 이상을 기준으로 한다. 자료형과 기본 연산 비용은 [Python data structures and functions](python-toolkit.md)를 따른다. 배열 인덱스는 0부터 시작하고, `[lo, hi)`는 `lo`를 포함하며 `hi`를 제외한다. 정렬과 탐색에는 서로 일관되게 비교 가능한 정수 키를 사용한다. 코드 옆의 예상 결과는 명세와 수작업 추적으로 도출한 값이다.

## 1. 정렬 기준과 안정성

### (1) 원본 변경과 반환값

`sorted(a)`는 정렬된 새 리스트를 반환하고, `a.sort()`는 리스트 `a`의 순서를 바꾸며 `None`을 반환한다. 따라서 원래 순서와 정렬 순서를 함께 사용해야 할 때는 두 결과를 별도로 보관한다. 특히 `a = a.sort()`는 정렬 결과를 받는 표현이 아니다.[1,3]

다음 표는 함수 호출 뒤 사용할 대상을 구분한다.

| 호출 | 사용할 결과 | 기존 리스트의 순서 |
| --- | --- | --- |
| `b = sorted(a)` | `b` | 유지 |
| `a.sort()` | `a` | 변경 |
| `b = sorted(a, reverse=True)` | 내림차순 `b` | 유지 |
| `a.sort(key=lambda r: r[1])` | 둘째 필드 기준 `a` | 변경 |

다음은 변경 효과만을 확인하는 수동 추적이다.[1,3]

```python
a = [8, 3, 8, 1]
b = sorted(a)
# a: [8, 3, 8, 1], b: [1, 3, 8, 8]
result = a.sort()
# a: [1, 3, 8, 8], result: None
```

원본 변경은 알고리즘의 입력 의미에도 영향을 준다. 예를 들어 작업을 도착 순서대로 묶어야 하는 문제에서 크기순 정렬을 먼저 하면 다른 문제를 풀게 된다. 뒤의 최소 용량 문제는 이 차이를 실제로 사용한다. “탐색에 정렬이 필요하다”는 말은 배열의 값에서 경계를 찾을 때의 조건이다. 정답 후보의 가능 여부를 탐색하는 경우에는 입력 배열 자체를 정렬할 필요가 없다.[4,5]

### (2) 안정성과 다중 키

Stable sort는 같은 키를 가진 레코드들의 상대적 순서를 유지한다. `key`가 반환하는 튜플은 첫 필드부터 비교하므로 `(주기준, 부기준)`의 우선순위를 표현한다. 여러 번 정렬할 때에는 낮은 우선순위부터 적용해야 마지막 정렬의 동률 안에 이전 순서가 남는다.[1,2]

레코드를 `(구역, 소요시간, 식별자)`로 정한다. 다음 자료는 구역 오름차순, 같은 구역에서는 소요시간 내림차순으로 배치하려는 예이다. 식별자는 동률을 관찰하기 위한 표시이며 정렬 키에 넣지 않는다.

```python
records = [(2, 5, "A"), (1, 4, "B"),
           (2, 7, "C"), (1, 4, "D")]
ordered = sorted(records, key=lambda r: (r[0], -r[1]))
# 수작업 예상: [(1, 4, 'B'), (1, 4, 'D'),
#               (2, 7, 'C'), (2, 5, 'A')]
```

이 예에서 음수 부호는 정수 소요시간의 비교 방향만 뒤집는다. 튜플 전체에 `reverse=True`를 적용하면 구역도 내림차순이 되므로 요구한 순서와 다르다. 다음 표는 실제 비교 키를 보여 준다. B와 D의 키가 같으므로 원래 먼저 있던 B가 앞선다.[1,2]

| 식별자 | 원래 필드 `(구역, 시간)` | 비교 키 | 결과 위치 |
| --- | --- | --- | --- |
| A | `(2, 5)` | `(2, -5)` | 3 |
| B | `(1, 4)` | `(1, -4)` | 0 |
| C | `(2, 7)` | `(2, -7)` | 2 |
| D | `(1, 4)` | `(1, -4)` | 1 |

같은 결과를 두 번의 안정 정렬로 표현하면 우선순위와 실행 순서가 반대임이 드러난다.[1,2]

```python
ordered = sorted(records, key=lambda r: r[1], reverse=True)
ordered.sort(key=lambda r: r[0])
# 첫 정렬: C, A, B, D
# 둘째 정렬: B, D, C, A
```

첫 정렬에서 시간 순서를 정한 뒤 둘째 정렬에서 구역을 묶는다. 둘째 정렬이 안정적이므로 한 구역 안의 시간 순서는 유지된다. 반대로 구역부터 정렬한 다음 시간을 정렬하면 전체 시간 순서가 주기준이 된다. 키를 하나 추가하는 행위도 의미를 바꾼다. `(구역, -시간, 식별자)`는 입력 순서 대신 식별자로 마지막 동률을 해소하므로, 안정성이 필요했던 이유를 먼저 확인해야 한다.[1,2]

정렬에서 말하는 동률은 레코드 전체가 같은지와 구분한다. 위 예의 B와 D는 서로 다른 작업이지만 구역과 시간이 같아 비교 키가 같다. 입력 순서가 도착 순서를 뜻한다면 안정 정렬은 도착 순서를 마지막 기준처럼 유지한다. 반대로 식별자 순서가 요구되었다면 안정성에 맡기지 않고 키에 식별자를 명시해야 한다. 따라서 키를 설계할 때는 두 레코드가 어느 조건에서 서로 앞뒤를 바꿔도 되는지를 먼저 정하고, 마지막까지 동률일 때 유지해야 할 순서가 무엇인지 결정한다.[1,2]

## 2. 병합과 분할의 원리

### (1) 정렬된 구간의 병합

Merge는 이미 정렬된 두 구간에서 다음에 출력할 가장 작은 원소를 선택한다. 두 입력의 맨 앞만 비교하면 되는 이유는 각 구간의 나머지 원소가 그 구간의 맨 앞보다 작지 않기 때문이다. Merge sort는 입력을 반으로 나누어 각 부분을 정렬한 뒤 이 연산으로 결합한다.[6,7]

아래 함수는 오름차순 정수 리스트 두 개를 받아 새 리스트로 병합한다. `i`, `j`는 각 입력에서 아직 소비하지 않은 첫 위치이다. 같은 값이면 왼쪽을 먼저 선택한다.[6,7,8]

```python
def merge_sorted(left: list[int], right: list[int]) -> list[int]:
    out = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            out.append(left[i])
            i += 1
        else:
            out.append(right[j])
            j += 1
    while i < len(left):
        out.append(left[i])
        i += 1
    while j < len(right):
        out.append(right[j])
        j += 1
    return out
```

불변식은 `out`이 소비한 원소 전체를 정렬된 순서로 담고, 아직 남은 어느 원소도 마지막 출력보다 작지 않다는 것이다. 시작 시 빈 출력은 이를 만족한다. 두 선두 중 작은 것을 붙이면 그 값은 남은 모든 원소의 최솟값이므로 불변식이 유지된다. 한쪽이 비면 남은 쪽은 이미 정렬되어 있으므로 그대로 이어 붙인다. 이것이 병합 단계에 적용한 귀납적 정확성 설명이다.[6,7]

`left=[2,5,5]`, `right=[1,5,9]`의 수동 추적에서는 동률 처리도 볼 수 있다.

| 선택 직전 `(i,j)` | 비교 또는 남은 쪽 | 추가한 원소 |
| --- | --- | --- |
| `(0,0)` | `2`와 `1` | 오른쪽 `1` |
| `(0,1)` | `2`와 `5` | 왼쪽 `2` |
| `(1,1)` | `5`와 `5` | 왼쪽 첫 `5` |
| `(2,1)` | `5`와 `5` | 왼쪽 둘째 `5` |
| `(3,1)` | 왼쪽 소진 | 오른쪽 `5,9` |

안정성을 레코드에 적용할 때에는 위 코드의 정수 비교를 키 비교로 바꾼다고 생각하면 된다. 원래 배열의 왼쪽 부분에 있던 동률 레코드는 오른쪽 부분의 동률보다 먼저 나와야 하므로, 병합에서도 왼쪽을 먼저 선택한다. 각 부분이 안정적으로 정렬되었다는 전제와 이 선택을 결합하면 전체 안정성을 얻는다. 단순히 “병합한다”는 사실만으로 모든 병합 구현이 안정적인 것은 아니다.[1,8]

두 입력 길이를 각각 $p$, $q$라고 하면 매번 한 원소를 소비하므로 위 함수의 시간과 출력 공간은 다음과 같다. 원소 접근과 비교, 리스트 끝 추가의 분할상환 비용을 상수로 둔다.[6,7]

$$
T_{\mathrm{merge}}(p,q)=O(p+q),\qquad
S_{\mathrm{out}}(p,q)=O(p+q).
$$

병합 전제는 두 입력이 같은 비교 기준을 공유한다는 것이다. 한쪽이 오름차순이고 다른 쪽이 내림차순이면 선두가 그 구간의 최솟값이라는 논거가 사라진다. 또한 두 입력이 원래 한 배열의 연속한 왼쪽·오른쪽 부분이었을 때에는 왼쪽 우선 규칙이 원래 순서를 복구하지만, 서로 다른 시점에 수집된 두 목록의 전역 도착 순서까지 알아내지는 못한다. 그 순서가 필요하면 도착 시각이나 일련번호를 데이터로 보존해야 한다. 이는 안정성 보장이 현재 입력의 순서에 대한 것이라는 정의에서 도출한다.[1,8]

### (2) 피벗을 기준으로 한 분할

Partition은 정렬되지 않은 구간을 피벗보다 작은 쪽과 크거나 같은 쪽으로 나누는 연산이다. 각 쪽의 내부 순서까지 완성하지는 않는다. Quicksort는 분할로 피벗의 위치를 확정한 뒤 양쪽을 재귀적으로 정렬한다.[7,9]

아래는 마지막 원소를 피벗으로 사용하는 Lomuto 방식이다. 조건은 `0 <= lo < hi <= len(a)`이며, 대상 구간은 `[lo, hi)`이다. 함수는 리스트를 변경하고 피벗의 최종 인덱스를 반환한다. 병합과 달리 이 구현은 원소 교환을 사용한다.[7,9]

```python
def partition(a: list[int], lo: int, hi: int) -> int:
    pivot = a[hi - 1]
    cut = lo
    for scan in range(lo, hi - 1):
        if a[scan] < pivot:
            a[cut], a[scan] = a[scan], a[cut]
            cut += 1
    a[cut], a[hi - 1] = a[hi - 1], a[cut]
    return cut
```

반복 시작 때 구간의 의미를 아래처럼 나눈다. `scan`이 앞으로 움직일 때 미검사 원소가 하나 줄어든다는 점이 진행을 보장한다.[7,9]

| 구간 | 반복 시작 시 보장 |
| --- | --- |
| `[lo, cut)` | 모든 값이 피벗보다 작음 |
| `[cut, scan)` | 모든 값이 피벗 이상 |
| `[scan, hi-1)` | 아직 분류하지 않음 |
| `hi-1` | 피벗 보관 위치 |

현재 원소가 피벗보다 작으면 `cut`의 원소와 교환하여 작은 구간에 넣는다. 그 자리에서 밀려난 원소는 피벗 이상인 구간으로 이동한다. 작지 않으면 검사 경계만 늘린다. 마지막에는 피벗을 `cut`으로 옮겨 두 구간 사이를 확정한다. 이에 따라 `[lo, cut)`과 `[cut+1, hi)`를 정렬하면 된다. 반환값을 다시 포함하는 재귀 호출은 구간 축소를 방해할 수 있다.[7,9]

수동으로 `a=[6,2,5,3]`을 분할하면 피벗은 3이고 결과는 `[2,3,5,6]`, 반환값은 1이다. 이 입력에서는 양쪽이 우연히 정렬되지만 일반 보장은 아니다. 예를 들어 작은 쪽이 `[2,1]`로 남아도 분할 조건에는 문제가 없다. 또한 교환이 동률 레코드의 상대 순서를 바꿀 수 있으므로, 이 분할 구현을 안정 정렬로 사용해서는 안 된다.[7,8]

피벗 선택과 동률의 배치도 비용에 영향을 준다. 위 구현에 같은 정수만 있는 리스트를 넣으면 `a[scan] < pivot`이 한 번도 참이 되지 않는다. 따라서 `cut`은 `lo`에 남고, 피벗 한 개를 제외한 모든 원소가 오른쪽 구간에 남는다. 값이 이미 같아 정렬 결과가 단순해 보여도 이 분할 규칙을 재귀적으로 반복하면 크기가 한 칸씩만 줄어든다. 이는 위 코드에서 직접 도출한 최악 입력이다. 무작위 피벗을 고르는 것만으로도 모든 값이 같은 입력의 이 현상이 사라지는 것은 아니다. 동률을 별도 영역으로 모으는 분할 등은 별도의 구현·분석이 필요하다.[7,9]

### (3) 비교 횟수와 추가 공간

길이 $n$인 입력을 다루는 기본 merge sort의 시간 $T(n)$은 균등한 두 재귀와 선형 병합으로 구성된다. 아래 식은 $n\ge2$에서의 점근적 관계이며 $T(0),T(1)=\Theta(1)$을 기저로 둔다.[6,7]

$$
T(n)=T(\lfloor n/2\rfloor)+T(\lceil n/2\rceil)+\Theta(n)
     =\Theta(n\log n).
$$

한 재귀 깊이에서 처리하는 부분 배열 길이의 합은 $n$이고, 깊이는 로그 수준이다. 따라서 깊이별 선형 작업을 합한다. 통상적인 배열 병합 구현은 크기 $O(n)$의 보조 저장 공간을 사용한다. 반면 quicksort의 분할은 균형이 깨질 수 있다. 한 원소만 확정하고 나머지 $n-1$개를 다시 처리하는 상황이 반복되면 다음 합이 생긴다.[6,7,8,9]

$$
(n-1)+(n-2)+\cdots+1=\frac{n(n-1)}{2}=\Theta(n^2).
$$

| 방법 | 핵심 작업 | 시간의 핵심 조건 |
| --- | --- | --- |
| Merge sort | 정렬된 절반들을 병합 | 균등 분할로 최악 $O(n\log n)$ |
| Quicksort | 피벗 기준으로 먼저 분할 | 균형 분할이면 $O(n\log n)$, 최악 $O(n^2)$ |
| 반복 이진 탐색 | 필요 없는 절반 제거 | 정렬·상수 접근 조건에서 $O(\log n)$ |

이 표의 정렬 비용은 비교가 상수 시간이라는 모형에 따른다. 길이가 커지는 문자열을 비교하거나 복잡한 키를 매번 계산하면 비교 횟수와 실제 비용을 구분해야 한다. 이진 탐색도 마찬가지이다. 각 단계에서 긴 문자열의 접두부를 비교한다면 단계 수가 로그라는 사실만으로 전체 시간을 $O(\log n)$이라 할 수 없다.[5,10]

비교 정렬의 $n\log n$은 단순히 특정 구현의 우연한 비용이 아니다. 서로 다른 원소 $n$개의 순서는 $n!$가지이며, 비교 결과만으로 올바른 순서를 정하는 알고리즘은 이 경우들을 구별해야 한다. 한 번의 이진 비교를 결정 트리의 갈림길로 보면, 높이 $h$인 트리는 최대 $2^h$개의 끝 결과를 구별한다. 그러므로 최악 비교 횟수에는 $h\ge\log_2(n!)=\Omega(n\log n)$이라는 하한이 있다. 마지막 등식은 점근적 하한을 나타내며, 모든 입력이 정확히 같은 비교 횟수를 요구한다는 뜻은 아니다.[11,12]

이 하한의 범위도 중요하다. 원소의 값을 배열 인덱스로 직접 사용해 빈도를 세는 counting sort는 비교만 하는 모형을 벗어난다. 정수 키가 $0$부터 $u-1$까지라면 입력 순회와 $u$개의 빈도 칸 순회를 합쳐 $O(n+u)$에 값을 정렬할 수 있다. 하지만 $u$가 매우 크면 빈도 배열 자체가 부담스럽다. 뒤에서 설명할 좌표 압축은 필요한 값만 작은 인덱스로 바꾸지만, 일반적인 압축 과정에도 정렬 비용이 들어가므로 압축을 했다는 이유로 최초 정렬의 하한을 피했다고 주장할 수는 없다.[11,12]

실제 원본을 바꾸는지와 보조 공간이 상수인지는 서로 다른 질문이다. 함수가 기존 리스트에 결과를 덮어써도 내부에서 임시 배열을 사용할 수 있다. 이 문서의 `merge_sorted`는 반환할 출력 배열을 직접 만들며, `partition`은 같은 리스트의 참조를 교환한다. 공간 비용을 비교할 때는 입력 저장 공간, 반환 결과 공간, 계산 중 추가 공간을 분리하여 세어야 한다. 특히 앞 표의 `list.sort()`가 원본을 변경한다는 계약만으로 메모리 사용량을 $O(1)$이라고 추론해서는 안 된다.[1,6]

## 3. 이진 탐색의 경계

### (1) Lower bound와 upper bound

오름차순 배열 `a`의 길이를 $n$, 질의 값을 $x$라 하자. Lower bound $L(x)$는 $x$ 이상인 첫 원소의 위치이고, upper bound $U(x)$는 $x$보다 큰 첫 원소의 위치이다. 해당 원소가 없으면 둘 다 가능한 삽입 위치인 $n$을 반환한다.[10,13]

$$
L(x)=\min\bigl(\{i\mid 0\le i<n,\ a_i\ge x\}\cup\{n\}\bigr),
\qquad
U(x)=\min\bigl(\{i\mid 0\le i<n,\ a_i>x\}\cup\{n\}\bigr).
$$

이 정의는 존재하지 않는 원소와 중복 원소를 같은 방식으로 처리한다. `a=[1,4,4,4,9]`에 적용하면 다음과 같다. 값이 4인 영역은 인덱스 1부터 3까지이므로 반열린 구간으로는 `[1,4)`이다.

| 질의 $x$ | $L(x)$ | $U(x)$ | 의미 |
| --- | --- | --- | --- |
| 0 | 0 | 0 | 처음에 삽입 |
| 4 | 1 | 4 | 같은 값 세 개의 양 끝 |
| 6 | 4 | 4 | 4와 9 사이에 삽입 |
| 12 | 5 | 5 | 마지막 뒤에 삽입 |

두 경계의 차이는 중복 개수이다. 이는 정렬된 배열에서 같은 값들이 한 구간에 모인다는 사실과 `[L,U)`의 길이가 `U-L`이라는 정의에서 바로 도출한다.[10,13]

$$
\#\{i:a_i=x\}=U(x)-L(x).
$$

### (2) 반열린 구간과 불변식

Lower bound 구현은 “답 원소를 찾으면 종료”하지 않는다. 아직 판정하지 않은 인덱스 구간 `[lo, hi)`를 줄여 모든 원소가 경계의 어느 쪽인지 확정한다. 다음 코드는 전체 배열을 대상으로 한다.[4,5,13]

```python
def lower_bound(a: list[int], x: int) -> int:
    lo, hi = 0, len(a)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if a[mid] < x:
            lo = mid + 1
        else:
            hi = mid
    return lo
```

배열이 정렬되어 있다는 전제 아래 불변식은 아래 세 부분이다. `hi`는 원소를 가리키는 인덱스일 수도 있고 배열 끝 다음 위치일 수도 있다. 수식에서 빈 구간에 대한 조건은 자동으로 참이다.[4,13]

$$
0\le lo\le hi\le n,\qquad
\forall i<lo:\ a_i<x,\qquad
\forall i\ge hi\ (i<n):\ a_i\ge x.
$$

초기에는 확정된 양쪽 구간이 모두 비어 있다. `a[mid] < x`이면 정렬성 때문에 `mid` 이하도 모두 작으므로 `lo=mid+1`이 안전하다. 그렇지 않으면 `mid` 이상이 모두 $x$ 이상이므로 `hi=mid`로 바꾼다. 이때 `mid` 자체가 첫 $x$ 이상일 수 있어 그 후보를 버리면 안 된다. 남은 원소는 `[lo,hi)`에 있지만 경계 위치의 후보는 `lo`부터 `hi`까지라는 차이를 구별한다.[4,5,13]

반복 조건 `lo < hi`에서는 `lo <= mid < hi`이다. 어느 분기를 택해도 음이 아닌 길이 `hi-lo`가 엄격히 줄어든다. 종료 때 두 경계가 같고, 그 왼쪽은 모두 $x$ 미만이며 그 오른쪽은 모두 $x$ 이상이므로 반환값은 정확히 lower bound이다. 초기화·보존·종료 결과와 종료 가능성을 나누어 확인하는 것이 불변식 증명의 구조이다.[4,5]

앞의 배열에서 $x=4$를 찾는 수동 추적은 다음과 같다.

| 반복 전 `[lo,hi)` | `mid`, `a[mid]` | 다음 경계 |
| --- | --- | --- |
| `[0,5)` | `2`, `4` | `hi=2` |
| `[0,2)` | `1`, `4` | `hi=1` |
| `[0,1)` | `0`, `1` | `lo=1` |
| `[1,1)` | 검사 없음 | 1 반환 |

Upper bound는 작은 쪽에 동률까지 포함한다. 아래 코드는 같은 구간 규약을 유지하며 조건만 `<=`로 바꾼다.[10,13]

```python
def upper_bound(a: list[int], x: int) -> int:
    lo, hi = 0, len(a)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if a[mid] <= x:
            lo = mid + 1
        else:
            hi = mid
    return lo
```

길이 $d>0$인 미검사 구간은 한 번 반복한 뒤 길이가 최대 $\lfloor d/2\rfloor$가 된다. 따라서 원소 접근과 비교가 상수 시간일 때 비교 횟수는 $O(\log(n+1))$이고, 반복 구현의 보조 공간은 $O(1)$이다. `n+1` 표기는 빈 배열도 포함하기 위한 것이다. 빈 배열에서는 처음부터 `lo==hi==0`이라서 배열 접근 없이 0을 반환한다.[4,5]

경계 갱신을 한 글자 바꾸면 종료 증명이 사라질 수 있다. 예를 들어 `a=[1,3]`, `x=2`에서 작은 쪽 분기를 `lo=mid`로 잘못 쓰면 처음 `mid=1`에서 `hi=1`이 되고, 다음 `mid=0`에서 `lo=0`이 된다. 이후 같은 상태가 반복된다. 찾는 원소가 없어서 생기는 문제가 아니라, 이미 판정한 `mid`를 미검사 구간에서 제거하지 않았기 때문이다. 반대로 큰 쪽 분기를 무조건 `hi=mid-1`로 바꾸면 반열린 규약에서 아직 가능한 경계를 지나칠 수 있다. 올바른 수정인지 판단할 때는 예제의 성공 여부보다 불변식과 길이 감소를 먼저 대조한다.[4,5]

불변식에서 오른쪽의 의미를 바꾸면 반환값의 의미도 함께 바뀐다. Lower bound는 동률을 오른쪽에 남겨 첫 위치를 찾고, upper bound는 동률을 왼쪽으로 넘겨 마지막 동률 다음 위치를 찾는다. 둘 다 값이 같다고 즉시 반환하지 않는 이유이다. 중복 없는 입력에서만 시험하면 두 구현의 차이가 드러나지 않을 수 있으므로, 같은 값 여러 개와 질의값이 전혀 없는 경우를 수동 추적에 함께 넣는 것이 경계 계약을 확인하는 데 유용하다.[10,13]

### (3) Bisect와 경계 질의

Python에서는 `bisect_left`와 `bisect_right`가 각각 위 두 삽입 경계를 제공한다. 반환값은 값의 존재를 직접 뜻하지 않는다. 존재 여부는 경계가 배열 안에 있고 그 자리의 값이 같은지 별도로 확인한다.[10,13]

```python
from bisect import bisect_left, bisect_right

a = [1, 4, 4, 4, 9]
x = 4
left = bisect_left(a, x)
right = bisect_right(a, x)
exists = left < len(a) and a[left] == x
count = right - left
# 수작업 예상: left=1, right=4, exists=True, count=3
```

같은 두 경계로 인접 원소를 구하는 식을 도출할 수 있다. 먼저 조건을 검사한 다음 인덱싱해야 빈 입력과 양 끝을 안전하게 처리한다.[10,13]

| 원하는 값 | 사용할 위치 | 존재 조건 |
| --- | --- | --- |
| $x$ 이상인 최솟값 | `left` | `left < n` |
| $x$ 초과인 최솟값 | `right` | `right < n` |
| $x$ 미만인 최댓값 | `left - 1` | `left > 0` |
| $x$ 이하인 최댓값 | `right - 1` | `right > 0` |

닫힌 값 구간 $[s,t]$에 속하는 원소 개수는 $s\le t$일 때 다음과 같다. 여기서 $s,t$는 배열 인덱스가 아니라 값이다. 범위의 오른쪽 경계에서 동률을 포함하므로 upper bound를 사용한다.[10,13]

$$
\#\{i:s\le a_i\le t\}=U(t)-L(s).
$$

```python
def count_between(a: list[int], start: int, stop: int) -> int:
    if start > stop:
        return 0
    return bisect_right(a, stop) - bisect_left(a, start)
# [1,4,4,4,9]에서 [4,8]의 개수: 4 - 1 = 3
```

이진 탐색 전에 매번 정렬하면 질의마다 정렬 비용을 다시 지불한다. 자료가 고정되어 있고 질의가 $q$개라면 한 번 정렬하고 경계를 반복 탐색하는 설계의 비용은 비교 정렬 $O(n\log n)$과 $q$번의 탐색 $O(q\log(n+1))$를 더한 것이다. 반대로 탐색 도중 자료나 키를 바꾸면 앞서 확보한 순서 보장이 사라질 수 있다. 이 구분은 전처리와 질의 비용을 분리하여 생각한 결과이다.[5,6,13]

정렬 전제가 실제로 필요한 지점은 값을 읽는 순간보다 절반을 버리는 순간이다. 예를 들어 정렬되지 않은 `a=[4,1,9]`에 `lower_bound(a,4)`의 규칙을 적용하면 중간의 1을 보고 앞쪽을 버린다. 다음에는 9를 검사한 뒤 위치 2를 반환한다. 실제 4는 위치 0에 있었지만 탐색에서 제외되었다. 이 직접 반례는 함수가 오류를 일으키지 않고도 잘못된 답을 줄 수 있음을 보여 준다. 결과 인덱스의 범위만 검사해서는 정렬 전제 위반을 발견할 수 없다.[4,5]

레코드 배열에서는 탐색할 필드가 실제 정렬 기준과 같은지도 확인한다. 구역으로 정렬한 레코드에서 소요시간만 뽑아 탐색하면 그 시간 배열이 정렬되어 있다는 보장이 없다. 앞의 `(구역, -시간)` 순서 역시 전체 시간의 오름차순을 뜻하지 않는다. 검색을 반복할 기준이 정해졌다면 그 기준으로 정렬한 키 배열과 레코드 배열을 대응시켜 두고, 둘의 위치 관계가 유지되도록 관리한다. 이는 앞서 설명한 다중 키 정렬과 lower bound 전제를 결합한 적용 조건이다.[1,2,10,13]

## 4. 단조 판정과 정답 탐색

### (1) 최초의 참 위치

이진 탐색에는 실제로 정렬된 배열이 없어도 된다. 정수 후보 $c$의 판정값 $P(c)$가 거짓에서 참으로 한 번만 바뀐다면, 최초로 참이 되는 후보를 탐색할 수 있다. 최적화 문제를 이 형태로 바꾸려면 “값이 얼마인가”보다 먼저 “이 후보로 조건을 만족할 수 있는가”를 판정해야 한다.[5,14]

후보 범위를 정수 반열린 구간 $[A,B)$로 정한다. 단조 조건과 찾을 경계 $c^*$를 함께 쓰면 다음과 같다. 참인 후보가 없을 때 $B$는 실패를 표시하는 반환 위치이다.[5,14]

$$
c_1\le c_2\ \land\ P(c_1)\ \Longrightarrow\ P(c_2),\qquad
c^*=\min\bigl(\{c\in[A,B):P(c)\}\cup\{B\}\bigr).
$$

아래 함수는 이 계약만을 사용한다. `predicate`는 같은 후보에 항상 같은 논리값을 반환하고, 실행 중 후보의 의미를 바꾸지 않아야 한다.[4,5]

```python
from collections.abc import Callable

def first_true(start: int, stop: int,
               predicate: Callable[[int], bool]) -> int:
    lo, hi = start, stop
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if predicate(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo
```

전제는 `start <= stop`이다. 반환값이 `stop`이면 범위 내에서 참인 후보가 없다는 뜻이며, `predicate(stop)`을 평가했다는 뜻도 아니다. 빈 범위 역시 그대로 `stop`을 반환한다. 모든 후보가 참이면 `start`가 나온다. 이들 결과는 lower bound에서 빈 배열, 전체 미만, 전체 이상을 처리한 방식에 대응한다.[5,13]

예를 들어 후보가 `[3,10)`이고 7부터 참이라면 다음처럼 진행한다. 이 표는 특정 응용 문제 대신 범위 규약만 수동으로 확인한다.

| 후보 구간 | 검사 후보 | 판정과 다음 구간 |
| --- | --- | --- |
| `[3,10)` | 6 | 거짓 → `[7,10)` |
| `[7,10)` | 8 | 참 → `[7,8)` |
| `[7,8)` | 7 | 참 → `[7,7)` |

판정 한 번의 비용을 $F(n)$, 후보 개수를 $W=B-A$라고 하면 탐색의 비용 상한은 다음과 같다. 자료 전처리가 있다면 그 비용을 별도로 더한다. 단순히 정답이 큰지 작은지 비교하는 비용과 실제 가능성을 계산하는 비용은 구분해야 한다.[5,10]

$$
T_{\mathrm{answer}}=O\bigl(F(n)\log(W+1)\bigr).
$$

판정 함수의 내부 상태는 호출마다 초기화해야 한다. 배치 수나 누적 작업량을 이전 후보의 판정에서 남겨 두면 같은 용량에 대한 결과도 검사 순서에 따라 달라질 수 있다. 바깥 반복은 중간값들을 작은 순서대로 검사하지 않으므로, 직전 후보에서 계산한 상태를 그대로 이어 쓰는 것은 별도의 갱신 논증 없이는 허용되지 않는다. 뒤의 `feasible` 함수가 매번 `batches=1`, `load=0`으로 시작하는 이유이다. 이 조건은 후보마다 같은 문제의 가능성을 판정한다는 정의를 구현 상태에 적용한 것이다.[4,5]

최댓값을 찾는 문제에서는 판정 방향부터 통일한다. 후보가 커질수록 가능에서 불가능으로 바뀌는 문제라면, 불가능 여부를 새 판정으로 삼아 최초의 불가능 위치를 찾고 바로 앞 후보를 취할 수 있다. 이때 범위의 첫 후보부터 불가능했다면 바로 앞 값은 범위 밖이며, 모든 후보가 가능하면 마지막 후보가 답이다. 최소화 코드의 분기 부등호만 바꾸기보다 어느 논리값의 첫 위치를 찾는지와 실패 반환값을 먼저 정하는 편이 같은 불변식을 재사용하기 쉽다. 이는 단조 판정의 방향을 뒤집어 적용한 직접 유도이다.[5,14]

### (2) 단조성과 경계의 실패 조건

단조성은 후보값이 정렬되어 있다는 사실로 자동 확보되지 않는다. 판정의 참·거짓이 후보 크기에 따라 어떻게 바뀌는지 증명해야 한다. 다음 표는 구간 규약을 유지하더라도 답을 보장하지 못하는 상황이다.[4,5]

| 빠진 조건 | 일어나는 문제 | 먼저 확인할 사항 |
| --- | --- | --- |
| 판정 단조성 | 버린 절반에 답이 남음 | 가능한 해의 포함 관계 |
| 답을 포함하는 범위 | 올바른 경계 밖에서 종료 | 하한·상한의 근거 |
| 참인 후보의 존재 | 끝 위치를 답으로 오해 | 실패 반환값의 해석 |
| 반복 중 자료 고정 | 같은 후보의 판정이 달라짐 | 상태 초기화와 변경 효과 |

구체적으로 후보 0, 1, 2의 판정이 `[참, 거짓, 참]`이라면 `first_true(0,3,...)`는 중간 1의 거짓을 보고 0을 버린다. 그 결과 2를 반환하지만 최초의 참은 0이다. 이는 단조 조건을 어긴 직접 반례이다. 실제 배열을 탐색할 때 정렬을 전제하는 이유도 동일하다. 중간값 하나로 한쪽 전체를 배제할 논리적 근거가 있어야 한다.[4,5]

정수 경계를 찾는 코드에서는 중간값도 정수로 유지한다. `(lo+hi)/2`로 부동소수점 후보를 만드는 것은 다른 문제이다. Python 정수의 표현과 큰 정수의 비용은 앞서 연결한 자료형 문서의 조건을 따른다. 다른 고정 폭 정수 환경으로 옮길 때에는 합과 중간값의 범위도 확인해야 하며, 이 문서의 `lo+(hi-lo)//2` 형태가 입력 합의 범위까지 대신 보장하지는 않는다.[5,11]

## 5. 순서 보존 분할의 최소 용량

### (1) 문제

작업량 `weights`가 주어진 순서대로 도착한다. 작업 하나를 나누거나 순서를 바꿀 수 없으며, 연속한 작업들을 하나의 배치로 묶는다. 각 배치의 작업량 합이 공통 용량 $C$ 이하이고 배치 수가 $k$ 이하가 되도록 하는 최소 정수 용량을 구한다. 다음 조건과 수치는 이 문서에서 구성한 문제이다.

| 항목 | 조건 |
| --- | --- |
| 작업 수 $n$ | $1\le n\le200000$ |
| 작업량 $w_i$ | 정수, $0\le w_i\le10^9$ |
| 허용 배치 수 $k$ | 정수, $1\le k\le n$ |
| 반환값 | 최소 정수 용량 $C^*$ |
| 예시 입력 | `weights=[6,2,5,8,3,7]`, `k=3` |

이 문제는 순서를 보존하는 연속 분할이다. 먼저 정렬하면 서로 이웃한 작업이 달라지므로 허용된 해의 집합도 달라진다. 아래 해법은 양수 입력에 대한 연속 분할의 이진 탐색 방법을 바탕으로, 0을 포함하는 비음수 입력까지 본문에서 증명한 것이다.[5,14]

### (2) 답

예시의 답은 **13**이다. `[6,2,5]`, `[8,3]`, `[7]`로 나누면 합이 각각 13, 11, 7이므로 용량 13은 가능하다. 용량 12에서는 아래에 보일 최소 배치 수가 4여서 불가능하다. 두 인접 후보 12와 13을 판정하고 단조성을 결합하면 최적값이 정해진다.[5,14]

다음 함수는 위 입력 계약을 전제로 한다. 빈 입력, `1 <= k <= n`을 만족하지 않는 배치 수, 음수 작업량은 `ValueError`로 거부한다. 정수형 여부와 작업 수·작업량의 상한은 따로 검사하지 않으므로 호출자가 지켜야 한다. 입력 리스트는 변경하지 않는다.

```python
def minimum_capacity(weights: list[int], k: int) -> int:
    n = len(weights)
    if n == 0 or not 1 <= k <= n:
        raise ValueError("require nonempty weights and 1 <= k <= n")
    if any(w < 0 for w in weights):
        raise ValueError("weights must be nonnegative")

    def feasible(capacity: int) -> bool:
        batches = 1
        load = 0
        for weight in weights:
            if weight > capacity:
                return False
            if load + weight > capacity:
                batches += 1
                if batches > k:
                    return False
                load = weight
            else:
                load += weight
        return True

    lo = max(weights)
    hi = sum(weights)
    # 최소 가능 용량은 닫힌 구간 [lo, hi] 안에 있다.
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if feasible(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo

# minimum_capacity([6, 2, 5, 8, 3, 7], 3)의 수작업 예상값: 13
```

여기서는 상한 `sum(weights)`가 반드시 가능하다는 사실을 사용하여 답 후보를 닫힌 구간 `[lo,hi]`로 유지한다. 앞 절의 일반 함수는 실패를 나타내는 배타적 끝 `stop`을 허용했지만, 이 함수의 `hi`는 실제 가능한 용량이다. 반복문 형태가 같아도 경계의 의미까지 같다고 보아서는 안 된다.[5,14]

### (3) 판정과 최적성의 해설

가능성 판정은 현재 배치에 다음 작업을 넣을 수 있는 동안 계속 넣고, 넘칠 때에만 새 배치를 만든다. 용량 $C$에서 이 방식으로 필요한 배치 수를 $g(C)$라 하면 판정은 $P(C)=[g(C)\le k]$이다. 개별 작업이 $C$를 넘으면 그 작업을 어느 배치에도 넣을 수 없으므로 즉시 거짓이다.[5,14]

이 탐욕적 판정이 맞는 이유는 다음과 같이 직접 유도한다. 탐욕적 분할이 처음 $j$개 배치로 처리한 작업 수를 $e_j$, 임의의 가능한 분할이 처음 $j$개 배치로 처리한 수를 $d_j$라 하자. 이미 전체 작업을 처리했으면 이후 끝 위치도 $n$으로 둔다. 보일 성질은 다음과 같다.[5,14]

$$
e_j\ge d_j\qquad(j=0,1,2,\ldots).
$$

$j=0$에서는 둘 다 0이다. $e_{j-1}\ge d_{j-1}$이라고 가정하자. 이미 $e_{j-1}\ge d_j$이면 부등식은 자명하다. 그렇지 않으면 탐욕적 방법이 다음 배치에서 $d_j$까지 처리하는 데 필요한 작업은 임의 분할의 $j$번째 배치의 뒷부분이다. 작업량이 비음수이므로 뒷부분의 합은 그 배치 전체 합보다 크지 않다. 따라서 $d_j$까지는 반드시 들어가며, 가능한 한 멀리 진행하는 탐욕적 끝 위치는 그보다 뒤이거나 같다. 귀납적으로 성질이 성립한다.

임의의 해가 $k$개 이내의 배치로 모든 작업을 끝낸다면 탐욕적 방법도 $k$개 안에 끝낸다. 따라서 탐욕적 배치 수가 $k$를 초과했을 때 거짓을 반환해도 가능한 해를 놓치지 않는다. 이 증명에서 비음수 조건은 단순한 입력 편의가 아니라, 앞부분을 제외했을 때 합이 커지지 않는다는 핵심 근거이다.[5,14]

다음은 예시 입력에 대해 판정 함수를 끝까지 개념적으로 적용한 수동 추적이다. 실제 함수는 $k$를 초과하는 순간 더 일찍 종료할 수 있다.

| 용량 $C$ | 탐욕적 분할의 합 | 필요한 배치 수 | $k=3$ 판정 |
| --- | --- | --- | --- |
| 12 | `8 / 5 / 11 / 7` | 4 | 거짓 |
| 13 | `13 / 11 / 7` | 3 | 참 |
| 19 | `13 / 18` | 2 | 참 |

용량 12에서 첫 배치는 `6+2=8`이다. 여기에 5를 넣으면 13이 되어 넘치므로 다음 배치가 시작된다. 둘째 배치의 5에 8을 넣어도 13이 되어 넘친다. 셋째 배치는 `8+3=11`이고 마지막 7은 넷째 배치에 들어간다. 용량 13에서는 첫 세 작업을 한 배치로 묶을 수 있어 배치 수가 3으로 줄어든다.

판정의 조기 종료는 최소 배치 수의 증명에서 나온다. 이미 현재까지의 작업에 $k+1$개 배치가 필요해졌다면, 뒤에 작업을 더 읽더라도 앞선 배치 경계를 없애는 해가 새로 생기지 않는다. 그럴 수 있었다면 그 해를 현재 접두 구간에서 자른 것만으로도 더 적은 배치의 접두 구간 분할을 얻어 앞의 최적성에 모순된다. 따라서 남은 입력을 순회하지 않고 거짓을 반환한다. 반면 아직 $k$개 이하라는 이유만으로 참을 반환해서는 안 된다. 처리하지 않은 작업이 새 배치를 요구할 수 있기 때문이다.[5,14]

단조성은 탐욕적 실행 결과를 비교하지 않고도 증명된다. 용량 $C$에서 가능한 분할이 있다면 더 큰 용량에서도 정확히 같은 분할을 그대로 사용할 수 있다. 따라서 가능에서 불가능으로 돌아가지 않는다. 이 포함 관계가 바깥 이진 탐색의 근거이고, 앞의 배치 수 증명은 안쪽 판정 함수의 근거이다. 두 증명은 서로 다른 역할을 한다.[5,14]

전체 합을 $S=\sum_{i=0}^{n-1}w_i$, 최대 작업량을 $M=\max_i w_i$라 하자. 작업을 나눌 수 없으므로 $C^*\ge M$이고, 전부 한 배치에 넣으면 $S$가 가능하다. 또한 $k$개 배치의 총 수용량이 전체 합 이상이어야 하므로 평균에서 오는 하한도 얻는다.[5,14]

$$
\max\left(M,\left\lceil\frac{S}{k}\right\rceil\right)
\le C^*\le S.
$$

코드는 단순한 하한 $M$을 사용한다. 평균 하한은 직접 도출한 강화 조건이며 최적값 자체는 아니다. 예시에서는 $S=31$, $M=8$, $\lceil31/3\rceil=11$이지만 연속성과 분할 불가 조건 때문에 답이 13이다. 합을 균등하게 나누는 산술만으로 실제 분할을 보장할 수 없는 이유이다.

코드의 초기 구간은 `8 ≤ C ≤ 31`이다. 아래 추적은 앞 절의 `first_true` 표와 달리 닫힌 답 후보 구간을 기록한다.

| 반복 전 `[lo,hi]` | `mid` | 배치 수 | 다음 `[lo,hi]` |
| --- | --- | --- | --- |
| `8 ≤ C ≤ 31` | 19 | 2 | `8 ≤ C ≤ 19` |
| `8 ≤ C ≤ 19` | 13 | 3 | `8 ≤ C ≤ 13` |
| `8 ≤ C ≤ 13` | 10 | 4 | `11 ≤ C ≤ 13` |
| `11 ≤ C ≤ 13` | 12 | 4 | `C = 13` |

한 판정은 최악 $O(n)$이고, 후보 구간은 로그 횟수만큼 줄어든다. 초기 최댓값·합·입력 검사는 선형이다. 아래 비용식은 $S=M$인 경우에도 전처리 비용이 남음을 포함한다. 입력 리스트를 제외한 추가 공간은 상수 개의 정수 상태이다.[5,14]

$$
T=O\bigl(n\,[1+\log(S-M+1)]\bigr),\qquad S_{\mathrm{aux}}=O(1).
$$

산술 한 번을 상수 비용으로 놓은 모형이다. 문제 제한에서는 전체 합이 최대 $2\times10^{14}$이며, 이는 위에서 정한 $n$과 $w_i$의 상한을 곱한 값이다. Python의 정수 표현으로 저장하되, 임의로 자릿수가 늘어나는 입력까지 같은 산술 비용을 주장하지 않는다. 정수 표현과 비용 모형의 구분은 선행 자료형 문서를 따른다.

최소 용량뿐 아니라 실제 분할도 필요하다면, 최종 용량을 구한 다음 같은 탐욕적 순회를 한 번 더 하며 배치가 바뀌는 인덱스를 기록할 수 있다. 탐색 도중 기록한 중간 용량의 분할은 최종 답에 대응하지 않을 수 있으므로 최종 판정과 구별해야 한다. 예시에서 최종 용량 13으로 순회하면 경계는 인덱스 3과 5이며, 결과 구간은 `[0,3)`, `[3,5)`, `[5,6)`이다. 반환값만 요구한 위 함수에는 경계 목록을 만들지 않아 상수 추가 공간을 유지했다. 경계를 출력하는 확장에서는 출력할 배치 수만큼의 저장 공간을 따로 센다.[5,14]

용량을 구하는 바깥 반복에서 `feasible(mid)`가 참이라고 즉시 반환하면 최소값을 보장하지 못한다. 예시의 첫 중간값 19도 가능하지만 더 작은 13이 가능하다. 참 분기에서 `hi=mid`는 현재 후보를 가능한 상한으로 보관하면서 더 작은 답을 찾는 동작이다. 거짓 분기에서는 단조성에 의해 `mid` 이하가 모두 불가능하므로 `lo=mid+1`로 이동한다. 따라서 매 반복 뒤에도 최소 답이 닫힌 구간 안에 남고, `hi`는 가능하다. 이 응용의 증명은 일반 함수의 실패 끝 위치를 가정하지 않고 문제에서 확보한 가능한 상한을 사용한다.[5,14]

### (4) 경계와 반례

0을 허용한 입력에서도 같은 증명이 성립한다. 0을 추가해도 배치 합이 증가하지 않으며, 전부 0이면 초기 하한과 상한이 모두 0이라 이진 탐색 없이 0을 반환한다. 경계의 예상값을 함수 계약과 비교하면 다음과 같다.

| 입력 조건 | 예상 결과 | 이유 |
| --- | --- | --- |
| `[0,0,0]`, `k=2` | 0 | 모든 합이 0 |
| `[9]`, `k=1` | 9 | 유일한 작업을 담아야 함 |
| `[6,2,5]`, `k=1` | 13 | 한 배치에 전부 포함 |
| `[6,2,5]`, `k=3` | 6 | 각 작업을 따로 담을 수 있음 |
| 빈 리스트 또는 `k=0` | `ValueError` | 정의한 문제 범위 밖 |

정확히 $k$개의 비어 있지 않은 배치가 필요해도 $k\le n$과 비음수 조건 아래 최소 용량은 같다. $k$개보다 적은 배치를 얻었다면 작업이 둘 이상인 배치를 쪼개면 된다. 각 조각의 합은 원래 합보다 커지지 않고, 배치 수를 하나씩 늘려 $k$에 도달한다. 이는 앞의 비음수 분할 성질에서 도출한 결과이며, “최대 $k$개”를 “정확히 $k$개”로 바꿀 때 필요한 추가 논증이다.[5,14]

음수 작업량을 허용하면 판정 구현은 깨진다. `[5,-4]`, `k=1`의 실제 전체 합은 1이므로 용량 1로 한 배치가 가능하지만, 코드는 첫 작업 5가 용량보다 크다는 이유로 거짓을 반환한다. 나중의 음수가 앞의 초과량을 상쇄할 수 있기 때문이다. 이 반례에서 더 큰 용량에서도 기존 분할을 쓸 수 있다는 단조성은 여전히 성립한다. 실패한 것은 바깥 탐색이 아니라 양수·비음수 전제에서 만든 하한과 탐욕적 판정이다.[5,14]

## 6. 좌표 압축과 순위 공간

### (1) 서로 다른 값과 순위의 대응

Coordinate compression은 크거나 드문 값을 정렬된 서로 다른 값의 순위로 바꾸는 방법이다. 값의 크기 자체보다 상대적 순서가 필요한 연산에 사용한다. 사용될 좌표를 미리 알고 있을 때, 좌표 최댓값에 비례하는 배열 대신 서로 다른 좌표 수에 비례하는 배열을 사용할 수 있다.[11,15]

서로 다른 좌표를 정렬한 리스트를 `coords`, 그 길이를 $m$이라 하자. 0부터 시작하는 압축 함수 $r$을 다음처럼 정의한다. 정의역은 `coords`에 실제로 포함된 값이다.[11,15]

$$
\mathrm{coords}[j]=x\ \Longleftrightarrow\ r(x)=j,
\qquad 0\le j<m.
$$

다음 코드는 정수 좌표의 압축을 보여 준다. 중복 원소를 제거한 뒤 정렬해야 같은 값에 같은 순위를 부여할 수 있다.[11,15]

```python
values = [90, -5, 90, 12]
coords = sorted(set(values))
rank = {value: i for i, value in enumerate(coords)}
compressed = [rank[value] for value in values]
# 수작업 예상: coords=[-5,12,90], compressed=[2,0,2,1]
```

| 원래 값 | 압축 값 | 복원 |
| --- | --- | --- |
| -5 | 0 | `coords[0]` |
| 12 | 1 | `coords[1]` |
| 90 | 2 | `coords[2]` |

순위는 중복 개수를 없애는 것이 아니다. `coords`에는 90이 한 번만 있지만 `compressed`에는 순위 2가 두 번 남는다. 따라서 원래 데이터의 등장 횟수를 유지한 상태에서 작은 인덱스로 집계할 수 있다. 이 결과는 압축 대상을 서로 다른 값의 목록과 전체 입력 목록으로 분리한 데서 나온다.[11,15]

해시 기반 매핑을 피하고자 하면 정렬된 서로 다른 좌표에서 lower bound를 구해도 된다. 다음 코드는 `coords`가 이미 만들어져 있고 각 `value`가 그 안에 존재한다는 조건을 사용한다.[11,13,15]

```python
compressed = [bisect_left(coords, value) for value in values]
```

이 버전의 변환 단계는 $O(n\log(m+1))$번 수준의 비교를 수행한다. 사전 매핑 버전의 연산 비용은 선행 자료형 문서에서 설명한 사전 비용 모형과 별도로 결합한다. 양쪽 모두 정렬 전처리 비용과 결과 배열의 저장 공간이 필요하다. 입력이 빈 경우 `coords`와 결과도 빈 리스트이며, 존재하지 않는 순위를 억지로 만들지 않는다.[11,13,15]

정렬 목록에서 원래 인덱스에 매기는 순서와 좌표값에 매기는 순위도 구분한다. `[90,-5,90,12]`의 두 90은 서로 다른 입력 위치에 있지만 같은 압축 값 2를 갖는다. 만약 두 90에 서로 다른 순위를 주면 동등성을 보존하는 좌표 압축이 아니라 각 원소에 순서를 부여하는 다른 표현이 된다. 범위 집계를 목적으로 할 때는 같은 값의 빈도가 한 칸에 모여야 하므로 동률 처리부터 압축 계약에 포함한다. 원래 위치로 결과를 돌려줄 필요가 있다면 `compressed`를 원래 입력 순서대로 만든 지금의 형태를 유지한다.[11,15]

### (2) 보존하는 정보와 잃는 정보

압축은 순서와 동등성을 보존한다. 정의역에 속하는 두 좌표 $x,y$에 대해 다음 관계가 성립한다. 이는 정렬된 서로 다른 목록에서 위치를 매기는 정의의 결과이다.[11,15]

$$
x<y\ \Longleftrightarrow\ r(x)<r(y),\qquad
x=y\ \Longleftrightarrow\ r(x)=r(y).
$$

그러나 간격의 크기는 보존하지 않는다. 위 예에서 원래 간격은 `12-(-5)=17`, `90-12=78`인데 압축한 인접 간격은 모두 1이다. 따라서 압축 인덱스의 차이를 길이·거리로 쓰면 안 된다. 구간의 실제 길이가 필요하면 `coords[j+1]-coords[j]`를 별도로 보존해야 한다. 이는 압축 정의에서 확인할 수 있는 직접 반례이다.[11,15]

| 필요한 정보 | 압축만으로 가능한가 | 추가로 보관할 값 |
| --- | --- | --- |
| 두 값의 대소 | 가능 | 없음 |
| 같은 좌표의 빈도 | 입력별 순위로 가능 | 순위별 개수 |
| 원래 좌표 | 역대응이 있으면 가능 | `coords` |
| 실제 거리·구간 길이 | 순위 차이로는 불가능 | 원래 좌표의 차이 |

새 좌표를 나중에 추가하는 경우도 구분해야 한다. 예를 들어 `coords=[-5,12,90]`에 0을 삽입하면 기존 12와 90의 순위가 바뀐다. 이미 순위 인덱스로 자료를 쌓았다면 매핑만 한 항목 추가해서는 해결되지 않는다. 고정 좌표 집합을 전제로 한 압축은 이런 동적 갱신을 자동 처리하지 않는다.[11,15]

### (3) 압축되지 않은 질의 경계

질의의 양 끝이 실제 좌표에 없어도 순위 구간을 찾을 수 있다. `start <= stop`을 전제로, `coords`를 대상으로 `bisect_left(coords, start)`와 `bisect_right(coords, stop)`을 구하면 원래 닫힌 값 범위 `[start,stop]` 안에 놓인 좌표 종류의 반열린 인덱스 구간이 된다.[13,15]

```python
coords = [-5, 12, 90]
start, stop = 0, 50
lo = bisect_left(coords, start)
hi = bisect_right(coords, stop)
# 수작업 예상: [lo,hi)=[1,2), 해당 좌표는 12
```

여기서 `hi-lo`는 서로 다른 좌표의 개수이다. 원래 데이터에 중복 좌표가 있다면 전체 원소 개수와 다를 수 있다. 원소 개수를 구하려면 중복을 유지한 정렬 배열에 같은 경계 탐색을 적용하거나, 압축 순위별 빈도를 따로 합산해야 한다. 예를 들어 입력 `[90,-5,90,12]`의 범위 $80\le x\le100$에는 좌표 종류는 하나지만 원소는 둘이다. 압축의 목적과 집계 대상의 차이를 보여 주는 수동 예이다.[11,13,15]

## 7. 선택 기준과 요약

정렬과 탐색은 호출 이름보다 보장하는 조건으로 선택한다. 아래 표는 앞의 구현들을 연결한 사용 기준이다.[1,4,5,6,13,15]

| 필요한 결과 | 사용할 도구 | 먼저 확보할 조건 |
| --- | --- | --- |
| 레코드 전체 순서 | `sorted`, `list.sort` | 키 우선순위와 원본 변경 허용 |
| 두 정렬 결과 결합 | Merge | 양쪽이 같은 기준으로 정렬됨 |
| 동률의 개수·구간 | `bisect_left/right` | 비교 기준과 배열 순서 일치 |
| 최소 가능 정수 | 단조 판정 이진 탐색 | 판정 정확성, 단조성, 후보 범위 |
| 드문 좌표의 인덱스화 | Coordinate compression | 고정 좌표 집합, 거리 보존 필요 여부 |

동률을 다루는 정렬에서는 안정성을, 이진 탐색에서는 양쪽 경계의 의미를, 정답 탐색에서는 판정 함수의 정확성을 각각 확인한다. 순서 보존 분할의 예는 입력을 정렬하지 않고도 이진 탐색을 사용할 수 있음을 보인다. 좌표 압축은 순서를 작은 인덱스로 옮기지만 값의 차이를 대신하지 않는다. 이 조건들을 구분하면 짧은 구현에서도 무엇을 증명해야 하는지 명확해진다.
